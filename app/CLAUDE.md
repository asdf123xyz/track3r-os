# app/ — screens, actions, bindings

- Owns the screens, overlays, action registry, built-in bindings and the main-loop glue. Must not: block or touch SD in a handler (long work is a `core::Job`, run in slices: `src/import_job.cpp`, `src/peak_job.cpp`), include `platform/` or `sim/`, write colour literals (themes only), reach the editor outside `dispatch()` (`src/session_access.h` is private; `tools/check_layers.py` fails other includers).
- Entry points (the frame; a feature's own entry points are in `app/ENTRYPOINTS.md`, grep its ID; the generated map `build-map/` from `python3 -I tools/code_map.py` gives every key's handler file:line and the files of any ID):
  - `include/o3os/app/app.h`: `App`, one main-loop pass, the `poll_*` steps
  - `src/actions.cpp` + `src/action_handlers.h`: constexpr action registry; handlers in `src/*_actions.cpp`
  - `src/bindings.cpp`: built-in `bind(context, gesture, action)` table, `kContextNames`
  - `src/screens/registry.cpp`, `include/o3os/app/screens/{screen,ids}.h`: one row per screen; a `Screen` only draws (no `on_action`)
  - `include/o3os/app/session.h`: editor, undo, macro recorder, jobs
- Add an action: handler in a `*_actions.cpp`, declare it in `action_handlers.h`, one `make_action()` line in `actions.cpp`, bind it in `bindings.cpp`. A model edit needs the `kActionUndoable*` flags so it is one undo unit (steps in the header of `include/o3os/app/actions.h`).
- Add a binding: one `bind(...)` line. A new Shift binding also goes in the Shift list at the top of the table and in `tests/builtin_bindings_test.cpp`, which fails until it is a decision. Moving or removing a binding that the manual draws as a key diagram (`docs/manual/diagrams.txt`, `bind =` lines) fails ctest `manual_diagrams` until you run `python3 tools/manual_diagrams.py`, commit `docs/manual/img/` and re-read the chapter.
- Add a screen: the recipe is the header of `include/o3os/app/screens/screen.h` and `docs/ui/style-guide.md` section 9 (class, `ScreenId`, registry row, bindings, sim states in `sim/src/screens*.cpp`).
- Tests: `tests/{actions,builtin_bindings,shift_labels,app}_test.cpp`, sim scenarios. Scoped: `ctest --test-dir build-os-host -L app -LE e2e --output-on-failure` (or `-R 'unit_rest|unit_ui|scenario_'`); `O3OS_CI_SCOPE=changed tools/ci.sh host` for a pre-commit run (usage in the header of `tools/ci.sh`).
- A visible change moves sim goldens: `cmake --build build-os-host --target update_goldens` (`O3OS_GOLDEN_ONLY=<scenario>` for one), then view the PNGs under `build-os-host/sim/png/`. Goldens are regenerated, never edited or merged by hand (details in `sim/CLAUDE.md`).
- Docs: `docs/ui/ui-map.md` (update the screen's row: F-keys, Shift row, bindings), `docs/ui/style-guide.md`, ADR 0009, `docs/specs/OS-*.md`.
- The manual follows this code (`docs/specs/OS-MANUAL2.md`). A key-row table (`kXxxSoftKeys` / `kXxxShiftKeys` in `include/o3os/app/screens/*.h`, `mixer_view.h`) feeds the key tables of `docs/manual/` through `tools/manual_tables.py`: after renaming a label run `python3 tools/manual_tables.py`, then `python3 tools/manual_llms.py`, and commit `docs/manual/` (`ci.sh host` fails on a stale table; keep each declaration `inline constexpr const char* kXxx[8] = {...};` with eight string literals; a label built at run time is hand-written in the chapter). Each manual section cites the files it describes (`<!-- sync: src=... -->`, locked in `docs/manual/sync.lock`): `python3 tools/manual_check.py --gate` (in `ci.sh host`) fails when a branch changes a cited file, such as `app/src/bindings.cpp` (cited by 18 sections), and neither the sections nor their lock lines changed. Re-read the sections, then run the one command the gate prints (`--ack-path app/src/bindings.cpp`) and commit `docs/manual/sync.lock`. After a merge, a conflict in `sync.lock`: take either side, then re-run `--ack-path <file>` (or `--ack-all`) on the merged tree.
- QA catalogue row, file `docs/qa/catalogue/<screen>.md`: `| ID | Function | How (gesture) | Expected | Sim | Unit | Spec | Status |`; ID `QA-<SCREEN>-NNN`, never reused; Sim cell `qa/qa_<screen>.txt › <snap>`. `ctest qa_cover` (`tools/qa_cover.py`) fails a row whose Sim snap, gallery picture, HIL step (Unit cell `qa_<screen>.json › <label>`) or host test does not exist, and a row that names none: write `manual: <reason>` in the Unit cell for what only a person can check (the older `by hand` stays valid only on a row unchanged since the base; forms in `docs/qa/catalogue/README.md`).
- Unit (hardware) steps: `platform/mk66/tools/hil/qa_<screen>.json`.
