# OS-005 — Audio engine and sequencer (ADR 0013)

Status: 005a, 005b merged; 005c built ("005c as built"); 005d-lite built ("005d-lite as built"); 005c2 specified 2026-10-11 · Source of truth: `docs/adr/0013-audio-engine.md`, including its Acceptance section. Maintainer rule: there is no audio engine on the PC. The host runs unit and reference tests of pure parts only, QEMU runs the Cortex-M4 paths, and hardware validates the rest in the `hw-session` gates HW-A…D.

## 005a — Engine skeleton (ADR 0013 D9 row "OS-005a", gate HW-A)
- **Memory map.** Extend `platform/mk66` `mem_map.h` with every ADR 0013 D7 region (sample arena, delay, modules, project arena, undo, UI cache, slack…) as `constexpr` with `static_assert` sums, and keep the generated linker script in step. Add a ctest that the map sums to 16 MiB of SDRAM with the stated slack, and that the SRAM_L/SRAM_U budgets hold.
- **Priority table.** The ADR 0013 D1 NVIC table goes in `hal::irq`; OS-007b started it, so complete and check it. Add the channel-ownership table (DMA channels, PIT, I²S) that designs out H11.
- **Audio HAL contract.** `hal::audio`:
  - `start()` after mute (H16);
  - a block callback contract;
  - the rate constant: cycles per sample as a rational number, one constant for 44,100 (the default since v1.0.0) and 44,117.65 Hz (ADR 0012 amendment).
- **MK66 implementation** (`platform/mk66/audio`):
  - I²S0 TX/RX with eDMA into a 3-slot ring (4 physical; 2 before OS-CPU10 slice 3, ADR 0013 amendment 6; one constant) of 64-frame stereo int16 blocks, with declared alignment and buffers in SRAM_U.
  - A tiny DMA half/complete ISR at the D1 priority that only pends the render interrupt; the render interrupt runs at the D1 deferred priority.
  - MCLK from I2S_MDR with the ratio from the rate constant.
 - SGTL5000 bring-up over I²C (Wire-free, our own minimal I²C master driver). Register values come from the SGTL5000 data sheet and PJRC's Audio library (`platform/mk66/sgtl5000.h` names the source of each), written fresh. Mute until stable.
  - Every hardware register sequence is cited to the K66 RM, as OS-007b did.
- **Render loop skeleton:**
  - per block, drain the (empty) ParamChange ring, render silence or a test signal (sine at a fixed frequency, from a phase accumulator in float, converted once per block per the D2 conversion point), and write the TX slot;
  - DWT cycle stamps per stage into an `AudioStatus` struct with single-writer atomics (H9/H10);
  - an underrun counter.
- **Load governor stub:** a budget of 60 % of the block period, with a counter when it is exceeded.
- **`diag`:** no CDC yet. Expose `AudioStatus` and the memory map through a pure formatter (`diag cpu`, `diag mem` text) that later binds to the console, and unit-test the formatter.
- **QEMU:** a fake I²S/DMA HAL on `mps2-an386`, using a timer interrupt as the block clock. It drives the same render path, so ctest checks:
  - priorities: the render never runs inside the DMA ISR;
  - ring-slot ownership under 10,000 blocks;
  - the underrun counter when render is forced slow;
  - the test-signal block content against a host reference.
- **Host:** unit tests for the pure parts: rate math, the test-signal generator, the ring slot state machine, the `AudioStatus` formatter and the memory-map sums.
- **Image:** the MK66 skeleton image gains a build variant (`O3OS_AUDIO_TEST=ON`) that plays the test tone after boot for HW-A. The default image stays silent. Both pass the OS-007b static checks: flash config, contiguity, reproducibility.
- **Done when:**
  - ctest passes on host, QEMU and MK66 with 0 warnings, and the static image checks pass on both variants.
  - Sizes are reported.
  - The reviewer approves, with a hardware-safety angle on DMA, I²S, MCLK and the SGTL5000 power-up order (pops, max volume at boot), plus a real-time angle.
  - The HW-A checklist is written: tone frequency against the rate constant, underruns over 10 minutes, DWT per stage, render jitter, mute at boot with no pop, and the 196/3125 MCLK retune trial.
- **Never flashed:** the image goes to the maintainer only through the firmware gate check and their decision.

## 005b — Fixed graph: tracks, buses, routing, master chain, meters, taps (ADR 0013 D4, D9 row "OS-005b", gate HW-A)
Builds on OS-005a, OS-002d (ParamChange, track mixer parameters) and OS-006a (stem ring).
- **Graph as a pure, block-based renderer.**
  - `render(block)` is callable from the MK66 render interrupt and, later, from an offline-render job in pull mode.
  - No virtual calls in the per-block path. The topology is a fixed table built at boot.
- **Track strips.** Track count, types and fields come from the OS-004a model. Each strip runs:
  - Σ input (voices arrive in 005d; until then a per-track test source: silence, sine or noise);
  - insert 1 and insert 2, both reserved and bypassed;
  - level and pan;
  - post-fader taps.

  The pan law and level curve are this OS's own (no legacy code copied); whether they match the official firmware's mixer is an open research question (Q).
- **Routing matrix.** Each track routes to MAIN, CUE, SNDA, SNDB, REC and USB through routing bits. Sends are pre-fader unless the project's SENDS setting makes them post-fader (PAR-024). SNDA → delay → return and SNDB → reverb → return are wired with bypassed processors until their behaviour is specified (strategy B; OS-SENDFX installs the effects).
- **Master.** The chain is `kMasterChain[]` in ADR 0013 D4 order B: headroom, saturation, EQ, bass, limiter, space, bit depth (EQ and bass moved ahead of the limiter by OS-DJ A3c, ADR 0013 amendment 5). Every insert point is reserved and bypassed until its behaviour is specified, except the limiter (OS-LIMIT: `audio/include/o3os/audio/master_limiter.h`, installed by the platform, always on: a look-ahead brickwall at -0.3 dBFS plus a slow stage with threshold / attack / release controls; new OS behaviour, not measured). CUE has its own cue level and OUT MODE (stereo MAIN, or MAIN L / CUE R; product-ux §4).
- **Inputs and monitoring** (radar card `monitoring-while-recording.md`, maintainer decisions).
  - Codec RX (LINE/MIC/RADIO, exclusive) becomes an external input bus with level and routing bits. It monitors through the engine by default, into MAIN/CUE.
  - Playback keeps sounding while the REC bus records.
  - The REC bus writes into a sample-arena stub (the sequential write path). Recording UI and files are later slices.
- **Parameters.**
  - Track level, pan, sends, master and cue levels are 002d ParamIds, applied from the ParamChange drain in the graph's pass, after the block's voices.
  - Gain and pan changes ramp across the block with a bounded per-sample step, so there is no zipper noise. The smoothing contract is shared with 005c.
- **Kernels.** Mix-accumulate, gain/pan with ramp, Q15/float conversion at the D2 point, sum and saturate, interleave for TX.
  - Each kernel has a scalar reference and an M4 SIMD variant (`__SMLAD`/`__QADD16`-style), with a portable fallback on the host.
  - The variants are tested against each other: bit-exact where integer, within a stated tolerance where float.
- **Meters and taps.**
  - Peak and RMS with hold and clip, per track, per bus and on the master, feeding `ui::plot` meters through a snapshot struct, never through audio buffers (ADR 0010).
  - Scope ring (master L/R, about 30 Hz).
  - Spectrum ring (512 mono frames; the rFFT runs in a job).
  - StemTap: mono int16 per track into the OS-006a stem ring.
  - `AudioStatus` gains per-stage DWT stamps.
- **MK66.** The render interrupt runs the graph instead of the bare test tone. `O3OS_AUDIO_TEST=ON` routes the test source through track 1 → MAIN, so HW-A also exercises the graph. The default image stays silent until voices exist.
- **Tests:**
  - routing truth table (every route bit and pan extremes);
  - pan law and level curve against independent formulae written out in the test (the laws are this OS's own model, `smoothing.h`);
  - ramp step bound;
  - meters against brute-force references;
  - rings under load with an overrun policy;
  - SIMD against scalar at random lengths and alignments;
  - the master chain bypass is bit-transparent;
  - a QEMU suite for the kernels;
  - host benches of cycles per block per stage as relative figures. MK66 cycle figures go to the HW-A checklist, with a budget table per stage against the 60 % governor.
- **Done when:**
  - Host, QEMU and MK66 ctest pass with 0 warnings, and the images are static-checked and reproducible.
  - Sizes are reported.
  - The reviewer approves, with a real-time angle (budget, no blocking, ring ownership) and a DSP-correctness angle.
  - HW-A gains: graph stage cycles, meters on the test tone, no clicks on level/pan sweeps, and input monitoring latency.

### 005b review decisions (2026-10-11, folded into the 005b commit series)
- **One saturation per bus (ADR 0013 D2).** MAIN reaches an active master chain as float straight from the Q19 accumulators (`kernel::acc_to_float_main`); the only clip is `float_to_q15` after the chain. Test: two tracks at 30,000 through a half-gain stage give 30,000, not 16,384. With every stage bypassed MAIN is rounded and saturated by `sat_clear_main`, bit-identical to what a chain-less bus is.
- **Level laws (PAR-023; amended by OS-007i).** Both laws are this OS's own model (`smoothing.h`); whether the official firmware plays the same curves is an open research question (Q). `LevelLaw::Og1114` (a name only, for the law of the projects older than v7: 0 = silence, 100 = unity, 0.4 dB a step) and `LevelLaw::Og12` (a name only, for the law of v7 and later projects, the INSTRUMENT volume only: 0 = silence, level 1 = -24.00 dB, levels 2..100 = 0.48 dB x (level - 50), **50 = exactly 0 dB**, 100 = +24 dB; a 101-entry law, this OS's model, chosen for compatibility: maintainer decision 2026-10-16 in ADR 0013 (PAR-023 level curve); no measurement of an official unit is in the repository, so an A/B on the unit is the open check). Both come from `level_gain_q16(level, law)` (boot / load, `exp2_fast`). The MIXER (track, sends, master, cue, input) ALWAYS uses `Og1114` (`LevelCurve`), whatever the project: the 1.2+ mixer law is unsourced and is not Og12 (row P1-1: the v7+ default of every mixer level is 86, +17 dB through Og12). The master field `LevelLaw` (0x104) of 005b is removed and its id retired. The voices apply the instrument law: `SampleDesc::gain` is a Q16 gain up to +24 dB, set by the loader from the stored volume through the law of the project file (`app::instrument_law`: version 7 or later is `Og12`, older is `Og1114`); a step's velocity stays linear and replaces it (open item). A voice's output is saturated to int16 (a 64-bit product), the graph sum cannot overflow (int16 strips at unity at most). Tests: both laws against double-precision references (`audio_voices_test`), the mixer unboosted at 86 and the 16-strip full-scale sum (`audio_graph_test`), the law by project version and `diag inst` (`og_samples_test`).
- **Instrument sound (OS-007k).** (1) *Amp envelope*, instrument envelope slot 0 (`SampleDesc::env`, `AmpEnvelope`): the sample player's envelope (not the generator that drives the other slots). Stages in groups of 8 samples, at least one each (0 ms = 8 samples), at most 65535: delay (silent, the sample runs under it), attack 0 to 1, hold, decay 1 to sustain, sustain, release to 0, then the voice is gone. NoteOff releases over the release time, NoteFade over 300 ms (1655 groups), a NoteOff in the delay ends the note at once, a second NoteOff restarts the release from the current level; `amount` multiplies the gain (velocity's included). It replaces the 32/256-sample attack/release ramps; disabled (or byte +18 set, the LFO case, TODO) is the old behaviour bit for bit and costs one compare a segment. Level Q30, amplitude Q24 (the voice's amp is now Q24 for every voice: 8 more bits, results bit-identical), linear segments at stage boundaries and block ends, one SDIV a segment. (2) *Pan*: `SampleDesc::pan`; where a note starts the Engine calls `Graph::set_voice_pan`, which gives the strip an offset (instrument pan - 50) added to the strip's own pan before the pan law, clamped to 0..100: with the strip at the centre (every project imported from an OG folder) it is the instrument's panning applied at note on, and an instrument at the centre leaves the strip's pan (a MED import's, the mixer's). Instant. Pan envelope, Pan FX: not yet. (3) *Play modes 2 and 3*: the backward and ping-pong loops: forward from the start to the loop end, there reflect about loop_end - 0.5 and run backward; backward loop: at loop_start jump to the end and keep running backward; ping-pong: reflect about loop_start + 0.5 and run forward. Differences: the sample after the loop is not read (held), a step larger than the loop is clamped inside it. (4) *Slice FX* (25): forces the slice of a beat slice instrument per track, `value % slice_count`, ModSet/ModEnd of group Slice and FxReset through the Engine. Tests: `audio_voices_test` (envelope against a double-precision reference, the loop walks against the reference walks of `tests/data/loop_walk_vectors.h` (the output of our own reference model; whether the official firmware's loops walk the same is Q), pan at 0/50/100 and combined, Slice FX), `og_samples_test` (ms to groups against recorded values, mode and pan binding).
- **Pan, finetune and amp modulators, live loop points (OS-MOD).** Envelope slots 1 (pan), 5 (finetune) and 0 when its loop byte is set (the amp LFO) are played, over `SampleDesc::pan_mod`, `tune_mod`, `amp_mod` (each a `FilterMod`, the cutoff modulator's descriptor): an ADSR (loop 0) or an LFO (loop 1; shape, rate, amount from `lfo[slot]`), the cutoff modulator's generator (`ModGen`, `fenv_eval` / `flfo_level`). PAN and FINETUNE: the output (-1..1) x 100 cut toward zero is added to the instrument's pan (held 0..100) or fine tune (held -100..100) (whether the official firmware adds it the same way is Q), evaluated once a block per voice; the finetune remakes the increment (`tuned_inc_q32`, position continuous), the pan is the TRACK's strip pan (`Graph::set_voice_pan`, smoothed over the block). AMP LFO (tremolo): gain x amount x level(shape, phase), the amp table's 24 rates (`kLfoRate[r + 5]`), the transport's phase, a Q23 multiplier evaluated every 16th sample and walked linearly, a pass over the voice's samples before the filter; a NoteOff here plays the plain 5.8 ms release for a looped amp envelope (what the official firmware does here is an open research question, Q). WT POS and GRAN POS: OS-GRAN (below). LIVE LOOP: a Wave edit that moves a loop point inside the same window and mode sends `inst_param::LoopStart` / `LoopEnd` (samples from the descriptor's data) on the engine's ring; the render, the descriptor's only writer while a voice plays, holds them to [0, length] and 2 samples apart and moves the descriptor and the voices that loop over it (a forward voice past the new end wraps by itself, backward and ping-pong voices are put at it); PCM, window, slices and loop mode stay the sample bank's handover (`voices.h` LIVE LOOP has the protocol). Tests: `audio_mod_test` (double-precision references for each target, span independence, live enable / disable, the loop), `mod_app_test`, `inst_live_app_test` (live equals rebuilt over the new slots).
- **Granular voice (OS-GRAN, PARITY: BASE-03).** Play mode 7 is a voice mode of the sampler pool (`SampleDesc::granular`, `gr_len`, `gr_pos`, `gr_shape`, the type in `loop_mode`; `voices.h` GRANULAR): a grain of the whole sample around the position, looped forward, backward or ping-pong, under a square, triangle or half-sine ("gauss") amplitude (this OS's own voice; whether it matches the official firmware's granular voice is an open research question, Q; the shape tables are generated at compile time: 501 half-sine entries in flash, the triangle a formula). Position Q32.32, plain 15-bit lerp at the real position, all reads held inside the sample (a deliberate choice of this OS). The loop runs from FLASH (`run_gran`, `O3OS_AUDIO_COLD`, one call a span a voice): SRAM_L got only the dispatch (+56 B of the ~860 left); a non-granular voice pays one extra compare for a looped direction mode and nothing else. Cost, counted from the disassembly (about 75 instructions a sample, 9 spilled registers): ~100 cycles a sample, ~6,400 cycles a 64-sample block, ~2.5% of the block a granular voice (a plain voice ~35 cycles a sample), DWT not measured. **PAR-125 / PAR-126 (1.7.0 granular edge pitch) is an OPEN QUESTION**: only the release notes describe it, so this is this OS's behaviour (open research question). Tests: `audio_granular_test` (geometry incl. u16 wrap and the edges, the three loop types against a real-valued reference at several pitches and shapes, a poisoned guard against reads outside the sample, span independence, a note's life), a host test of the tables against recorded vectors, `og_samples_test` (the binding).
- **Full wavetable (OS-GRAN, PARITY: BASE-04).** The descriptor of a wavetable says its window and how many the stack has (`wt_pos` of `wt_windows`; `data` is that window, the loader's pick, as before), and the window moves: the live `inst_param::WtWindow` (0x12, a whole window number, not a model parameter: a Wave screen edit or a position FX would send it; the render writes the descriptor's `data` and the sounding voices, held to the stack) and the WT POS modulator (below). This OS does not crossfade between windows during playback (what the official firmware does is an open research question, Q). Window sizes 32..2048 and the pitch law were already the loader's and `wavetable_inc_q32`'s. `inst_param::GranPos` (0x13) is the granular position's live edit, taken at the grain's next wrap. NOT here: the FX 22 Position and FX 36 Position LFO (the sequencer's forced window / position: not routed to the voices yet). Cost: a window move is one pointer on a voice's block, in flash; a plain voice pays nothing. `voice_state` row 24 -> 28 KiB. Tests: `audio_wavetable_test`.
- **WT POS and GRAN POS modulation (OS-GRAN, PARITY: BASE-06).** Envelope slot 3 (a wavetable with more than one window) and slot 4 (a granular instrument) are played over one `SampleDesc::pos_mod` (a `FilterMod`, the same generator as the other modulators, `kMgPos`, `kMmPos`), with this rule (whether the official firmware computes it the same way is Q): output (-1..1) x windows (WT) or x 65535 (GRAN), cut toward zero, added to the instrument's window / position and held to the stack / 0..65535. Evaluated once a block per voice in `mod_block` (flash), like the pan and finetune; a wavetable voice re-points its window at that block (a hard step: no crossfade), a granular voice takes the position at its grain's next wrap. Live enable / disable / kind change follow `remod` (disabling returns to the instrument's window / position). `sample_desc_reads` now names all six slots; Params dims WT POS for a non-wavetable and GRAN POS for a non-granular instrument ("WAVETABLE ONLY" / "GRANULAR ONLY" in the info line; goldens `params_worst_*` regenerated). Cost: a voice without the modulator pays the existing one `mmask` test a span; with it ~a few hundred cycles a block (float generator + one pointer or one flag), not per sample. Memory: SRAM_U (`voice_state`) +3.7 KB (28 B a descriptor x 65, 52 B a voice x 12, granular fields), SRAM_L +4 B. Tests: `audio_wavetable_test` (ADSR / LFO against a window reference, held to the stack, off live, granular position follow), `og_samples_test` (the binding), `inst_live_app_test` (the invariant with descriptors of each kind).
- **Wavetable formats on import (OS-GRAN, BASE-04; no format change).** A wavetable is the OG's own shape: sample type 1, play mode 6, `wavetable_window_size` (u16, 32..2048, a power of two), window 0; the windows are length / size, so Serum's frame size and Surge's frame size and count FIT the existing INST fields (no version bump, no loader change). (1) **Serum WAV**: the importer reads the `clm ` chunk (`<!>2048 ...`: the first number is the frame size) into `wav::Info::wt_frame`; a malformed or duplicate chunk is dropped and counted (`Report::clm_ignored`, `FormatReport::sanitised`). (2) **The rule** (`wav::wavetable_frame`, `ReadParams::wavetable`): default `kWtAuto`: a marked WAV is a wavetable, a plain WAV is a SAMPLE (most WAVs are, and a length that happens to divide by 256 says nothing); override `kWtDetect` ("load as wavetable"): the marker's size, else the largest of 2048, 1024, 256 that divides the length (none: a sample); an explicit size 32..2048 over the marker's; `kWtOff`: never. A marker or request the engine has no table for (4096, 1000, less than one window) leaves a sample and is counted; a tail shorter than a window is not played and is counted. (3) **Surge .wt** (`wt::SurgeReader`, id `surge-wt`): `vawt` + u32 n_samples + u16 n_tables + u16 flags, then the tables, float32 or int16 (flag 4; flag 8 = 16-bit, else the 15-bit form, ASSUMED full scale at +-16384 so x2 saturated: header comments only, OPEN QUESTION against a real file); frame sizes outside 32..2048 / power of two (Surge allows 4096) are refused Unsupported; metadata after the audio is not read. Source: the Surge XT wavetable header (fetched 2026-10-13), its int16 scale constant is not in it. Tests: `wavetable_import_test` (crafted files: valid, truncated at every offset, wrong sizes, one-byte and blocking sources, the registry). **Load screen (new Community OS behaviour):** the listing shows `.wt` beside `.wav` (`ListFilter::extension2`); a `.wt` is read by `wt::SurgeReader` (its own FormatDesc in `SampleBankMem`, chosen by the name in `App::start_wav_load`), and F7 WT cycles `WavView::wavetable` (the soft key shows it: WT AUTO, WT LEN, WT 256 / 512 / 1024 / 2048, WT OFF) for the next LOAD / ADD; F5 on a `.wt` has no preview (the audition reads a WAV). Not saved: a screen preference. `sample_load_test` goes from the card through the job to the engine's descriptor (`wt_size`, `wt_windows`); `sampleload_*` goldens regenerated (F7 label).
- **Instrument filter (OS-007l).** `SampleDesc::filter` (enable, type 0 low / 1 high / 2 band, cutoff 0..1, resonance 0..4.3), `audio/svf.h`: a state variable filter (Chamberlin at 2x, the structure of the Teensy Audio library's public filter) in float, after the voice's gain, envelope and declick residual (player -> filter -> amplifier). This filter's law: cutoff 0..1 maps onto 478 exponential steps, 20 Hz x 2^(i/50) for i = 0..477, and `f = 2 sin(pi fc / (2 fs))` with fs 44117.647; Q = resonance + 0.7 held to 0.7..5. Whether the official firmware's filter has the same law is an open research question (Q). Coefficients per note and per Cutoff FX, not per block. A disabled filter is bypassed bit for bit; state per voice, kept across a retrigger that filters on both sides, cleared on any other start; the filter's tail is not carried once the voice is gone. *Cutoff FX* (27 Low-pass, 28 High-pass, 29 Band-pass): value/100 is the cutoff, the type is the FX's, the filter is on whatever the instrument says (resonance: the instrument's, else Q 0.7: ASSUMPTION; the original firmware's value here is an open research question); ModSet/ModEnd of group Filter and FxReset through the Engine; it acts on the sounding voice and the next notes, and its end restores the instrument's filter. **Not done:** the Filter LFO FX (35), the performance layer's cutoff and type (slot 2's ADSR and LFO are OS-007m, next). Cost: about 49 cycles a sample worst case (29 instructions, six `vfma` at 3 cycles), 3.1k cycles (17 us, 1.2 % of the 1.45 ms block) per filtering voice per block, all 8 voices 9.8 %: estimated from the compiled loop with the Cortex-M4F timings, not measured on the unit. Tests: `audio_svf_test` (a port of the Teensy fixed-point loop as reference, worst difference 1 LSB over 3 types x 4 cutoffs x 3 resonances x impulse, sweep and noise; the 478 cutoff steps; bypass; stability at Q 5; the voices through the reference; span independence; the Cutoff FX), `og_samples_test` (binding).
- **Filter modulation (OS-007m).** Instrument slot 2 (`SampleDesc::filter.mod`, `FilterMod`) modulates the cutoff, ONE of two as the instrument's loop byte picks: an ADSR (enable, loop 0) or an LFO (enable, loop 1; shape / rate / amount from `lfo[2]`). It runs only when the instrument's own filter is on (a filter that only the Cutoff FX turned on has no modulator). Cutoff = clamp(base + mod, 0, 1), base the Cutoff FX's value when the track has one, else the instrument's. **Timing (new Community OS behaviour; the original firmware's update timing is an open research question):** the cutoff is re-evaluated inside the render at every 16th sample of the 64-sample block (aligned to the block, so the output does not depend on how events cut the block) and held between, with the stage times in ms at the engine's rate: an update every 0.36 ms. ADSR: delay (the previous note's level on a retrigger, else 0), attack (linear from there to `amount`, never below it, never past 1), hold, decay (to sustain x amount), sustain, release from the level the last evaluation had (a NoteOff, NoteFade; in the delay it ends the modulation); the output is held to +-1. LFO: locked to the sequencer (the speeds are tempo-synced): the phase is the transport's tick count (576 a step from the play start) plus 576 x (the step the note started in % 36), over a period of 576 x rate ticks (whole ticks), rate being `lfo.speed` 0..28 into the 29 tempo-sync rates (128 steps.. 1/64; a third of a step is 191 ticks); shapes saw A(2u-1), reverse saw A(1-2u), triangle, square, random (a new level in [-A, A) a period). The Engine feeds the voices the Step events (they snap the tick count to the step grid, so swing does not move it), FxReset (the transport start) and, new in `EventSource::tempo`, the sequencer's tempo once a block (a Tempo FX takes effect from the next block); between Step events the count runs by the tempo and is held at the step's last tick. This OS's choices, with what the official firmware does an open research question (not captured on a unit): the step shift uses the song cursor's step, not track 0's; with the transport stopped the LFO runs on at the tempo in force (OS-BUG-WTLFO, `docs/specs/OS-LFOLIVE.md`: it held where it was); the random shape's first level is drawn at the note; the Filter LFO FX (35) and the performance layer are not here. A voice with no modulator is bit for bit what it was. Cost, estimated from the compiled code (Cortex-M4F, `-O3`): about 120 cycles an evaluation (the cutoff coefficient, one UDIV or VDIV), 4 a block, plus three more filter calls: about 0.55k cycles (0.2 % of the block) per modulated voice, 4.4k (1.7 %) with all 8; flash about +2.2 KB, SRAM about +2.0 KB (a 24-byte `FilterMod` in each of 64 sample slots, 60 bytes a voice), not measured on the unit. Tests: `audio_filter_mod_test` (double-precision references for the stage times and levels, the release, the retrigger, the clamps, the five shapes at known phases, the period against the tempo, the transport lock and step shift, the Cutoff FX base, span independence, sanitising, and the whole path through the Engine), `og_samples_test` (binding).
- **Performance filter (OS-011b).** The Perform screen's low-pass, high-pass and band-pass slots reach the voices through the control table's performance layer (`seq/control.h`): a ModSet of the Filter group with layer `kLayerPerf` whose value carries the slot's type (high byte) and a cutoff offset -100..100 (low byte; `audio/events.h perf_filter_value`). The voices (`VoicePool::set_filter_perf` / `clear_filter_perf`, `FilterFx` padding: no SRAM) turn the filter on with that type and set the cutoff to base + offset / 100 held to 0..1, the base being the track's Cutoff FX value when it has one, else the instrument's; clearing it returns the Cutoff FX or the instrument's own filter. The layer wins over the sequencer's columns and is its own: the transport start ends the sequencer's FX and not this one: `ControlTable::reset_columns` replaces `reset` at a fresh run, and the voices' FxReset leaves the layer. The other performance FX (volume, panning, sends, position, the LFO speeds, reverse) are sent to the control table and arbitrated, but no voice acts on them yet; the Filter LFO FX 35 is still not here. OS-PERFFX P0 (2026-10-18; `docs/specs/OS-PERFFX.md`): `Engine::dispatch` hands `VoicePool::fx_event` the whole event, which keeps the layer's value of the Overdrive and Bit depth groups and the strips' perf fields beside the filter; none of them is touched by FxReset or Stopped, and an export puts the whole layer (the filter too) away at `offline_enter` and brings it back at `offline_leave`: before, a held filter coloured the export's notes and the export's own Cutoff FX ended it. The slot bank and its commands are `seq/perform.h`. Tests: `audio_perform_test` (against the same voice with the equivalent instrument filter, the priority and the release, FxReset, the whole path through the Engine), `seq_control_test`, `seq_sequencer_test`.
- **A gain that carries no signal does not ramp.** A silent strip (no source, shut fader, underrun mute) snaps all its smoothers (level, sends, every dest pan gain) to their targets, so a route closed while the track was silent stays closed when it returns. Test: mute, close MAIN, unmute leaks nothing, with and without a live source.
- **Solo and the sends (Community OS choice; the official firmware's live behaviour is an open research question, Q).** A live SOLO is a mute of every other track, and by default the mute also mutes that track's delay and reverb sends. **Note:** one reading of the official manual's description of solo in live play and in export (its words are not copied; not verified) matches the other function, an export solo that mutes only the others' amplifiers and keeps their sends. The code implements both: `set_solo_mutes_sends(true)` is the default and is the live mixer's; `false` is the export's reading, for OS-005g. Flip the default if the maintainer decides otherwise (one constant, tested both ways).
- **Bypassing a send effect closes its input and lets the tail ring out** (the effect is handed silence and is still run, so a delay's repeats and a reverb's tail finish; bypass is not a cut). A slot with no processor has no return. It takes effect when real effects arrive (005e); the test doubles in `audio_graph_test` pin it (`graph.cpp` `run_buses`).
- **CPU cuts** (all bit-exact against the unfused references): two tracks that open MAIN go through one fused strip pass, a centre-panned track adds into one centre accumulator (one multiply a sample), meters are maskable (`set_meter_mask`, all on by default) and the scope and spectrum rings are written only while a consumer asks (`set_scope_enabled`, `set_spectrum_enabled`, off by default); the stem staging copy only while the tap is on and the USB bit set.
- **Memory.** `audio::TapMem` (stem pool and ring, scope, spectrum, meter words) is placed by the platform: SRAM_L (`.tapmem_l`, NOLOAD) on the MK66; the two shared track scratch blocks replace one block per track. The graph's working buffers stay in SRAM_U.
- **Layering.** `audio` no longer includes the model: `configure(active_mask)` takes the tracks that sound, the strip and master ParamIds are re-exported as `audio::graph_param::*` and `audio::strip_param / master_param`, and `tests/audio_model_ids_test.cpp` holds them equal to the model's at compile time.
- **Rounding.** Conversions round to nearest (half up): the Q19 accumulator rounds through SMLAWB's accumulate operand and SSAT's free shift, `mono_mix` through a rounded average. Null tests (D8): one track is the ideal product within 1 LSB at any level and pan; a mix of twelve has a mean error within 0.15 LSB (the residual is the floor of each attenuating pan product in the Q19 accumulator, -1/32 LSB) and no sample off by more than 4.

## 005c — Sequencer v2 and MIDI timing core (ADR 0013 D5 and D9 row "OS-005c"; radar card `midi-clock-sync.md` and its maintainer decisions)
Builds on OS-005b. This slice is pure and host-tested; the device drivers come in 005c2.
- **Sequencer:** a pure `step(block_start, n) → events[]` over a `uint64` sample timeline.
 - **Timing.** Tempo is samples per tick in Q32.32, with no float drift. Grid: 192 PPQN = 48 microsteps per step. Swing uses this OS's pair arithmetic (new Community OS behaviour; checked against the reference vectors of the step timing, `tests/data/seq_oracle_vectors.h`, the output of our own reference model; whether the official firmware's swing is the same is an open research question). PAR-081 swing FX and PAR-082 tempo FX change the next step's duration. Core FX 43 Speed, 44 Tempo fine and 45 Order jump come from ADR 0004 amendment 1.
  - **Events** carry a sample offset 0..n−1.
  - **FX handling.** Row FX are expanded at step time. Per-tick FX (roll, arp, gate length) become sub-step events. Continuous FX (LFO, glide/slide) are emitted as modulator events for the voices of 005d.
  - **Control layers** (sequencer, sequencer 2, performance; BASE-20): a per-parameter source table, pure.
  - **Playheads and switching.** Playheads: song cursor, per-track pattern cursor with its own length, and the performance layer. Song and pattern switch at pattern end without stopping (PAR-021).
  - **Transport:** play, stop, continue, loop, and position from the song cursor.
  - **Row reads.** Rows come from the model arena with a generation check and a 96 B row copy. The render never asks for SD (preload is OS-004a's).
  - **ParamChange.** The drain plus smoothing is shared with 005b's ramp contract.
- **MIDI timing core**, pure:
  - **Out:**
    - due sample times go into a `midiOut` timed queue;
    - an emitter state machine implements "clock is sacred" (real-time bytes F8/FA/FB/FC are inserted between the bytes of any other message, and clock timing never waits for SysEx or a CC burst);
    - a byte-time model of DIN at 31,250 baud, used to predict jitter against the targets: ≤ 50 µs on an idle wire, ≤ 320 µs on a busy one;
    - USB MIDI packets quantised to 1 ms;
    - hang bookkeeping (PAR-063).
  - **In:**
    - timestamped bytes go through the `midiRt` ring;
    - a clock-follow DLL/PLL (24 PPQN in, slews phase, never jumps) with per-port offsets;
    - Start, Stop, Continue and SPP become transport events;
    - PAR-119 clock correction is reserved until its behaviour is specified.
  - **Lock and drift tests** against simulated external clocks: steady, ±1 % drift, jitter ±1 ms, a tempo ramp, dropouts, Start mid-bar and SPP jumps. The report gives lock time and steady-state phase error.
- **Tests:**
  - tests against the reference vectors, the output of our own reference model (swing, step duration, micromove, roll/note length), with golden event dumps for synthetic patterns;
  - offline-render determinism: the same events whatever the block size;
  - the emitter's insertion properties (no clock byte ever late by more than one byte time in a fuzzed message stream);
  - the DLL figures;
  - a QEMU suite for the pure code.
- **Done when:** host, QEMU and MK66 ctest pass with 0 warnings; the reviewer approves with a timing-correctness angle; the figures are recorded for the HW-B timing gate.

### 005c as built (2026-10-11)
**Where it lives.** `core/qtime.h` (Q32.32 time), `audio/events.h` (`SeqEvent`), the new library `midi` (`midi`: message, timed queue, DIN emitter, USB out, hang book, router, MIDI in, clock-follow DLL) and the new library `seq` (`seq`: FX table, control layers, row reader, RNG, sequencer). Layer rules (`tools/check_layers.py`, self-tested): `midi` may include core, usb, hal, audio; `seq` core, usb, hal, audio, model, midi; `platform` may include `midi` (005c2 binds the emitter), not `seq`. The audio layer still does not include the model: the event struct is in `audio` so that the voices of 005d can consume it.

**What it does** (this OS's own model, new Community OS behaviour: every behaviour below is backed by the reference vectors (the output of our own reference model, maintainer 2026-10-18) or the tests named, or listed in the open items; whether the official firmware behaves the same is an open research question, Q):
- **Timeline.** Tempo is samples per 192-PPQN tick as Q32.32 (`core::samples_per_tick_q32`, exact rational arithmetic over the one rate constant: a million steps are exact to 0.003 sample). Microstep j of a step that starts at S and lasts D is at S + D·j/48, rounded to the nearest sample; the origin is a whole `uint64` sample and the offset a Q32 that the sequencer moves on every 6.7 hours. Events carry the sample offset 0..n-1; an event whose time has passed (a command that lands mid-block, a backlog) comes out at offset 0 and is counted (`late_events`). The same events come out whatever the block size (`seq_determinism_test`, sizes 1 to 1000 and a random walk, one pinned hash).
- **Swing** is this OS's pair arithmetic: a step lasts `nominal × (150 − s)/100` (even steps of a run) or `(50 + s)/100` (odd), s 25..75, straight at 50, the pair parity counted from the run's first step. Checked against the reference vectors of the step timing for tempos 40..800 and swings 25..75 (a host test, to one sample).
- **Rows.** At the first microstep of a step each track copies its row (7 bytes, `read_step`, with the generation check: two attempts, a torn row reads as empty and is counted), sanitises the FX (`fxtable::sanitize`'s rules) and runs the pre-effects in the reference order, second column first. Micro-move delays the note by 0..46 microsteps (the value 0..100 scaled linearly onto 1..48, less one); Roll is the value 9 × direction + period, repeats on the microstep grid of its period (a 1/4 roll at microstep 13, 25, ...: the first repeat a microstep late), each note half a period long, directions const / note up / note down / volume up / volume down; Gate; Off, Cut, Fade; the velocity FX (the value 0..100 scaled onto 0..127); Chance (a draw in 0..99 above the value cancels the note, so 100 always plays), Random note / instrument / velocity / value from a seeded xorshift reseeded at every run; Tempo FX (value × 2 BPM, below 40 is 40, PAR-082), Swing FX (PAR-081), core FX 43 Speed (Tick events, off unless `emit_ticks`), 44 Tempo fine (`(v − 128)/4` BPM), 45 Order jump, 13 Break pattern. The reference model's counters (a step stays open 9999 microsteps, a roll goes on through a Cut) are kept. The reference vectors (400 random patterns, tempo and swing FX included) agree with the sequencer on 124,502 events (new Community OS behaviour; the official firmware's agreement is an open research question).
- **Control layers** (`seq/control.h`): this OS's priority rule per parameter GROUP (the filter FX 27/28/29 are one parameter; new Community OS behaviour, the official firmware's rule is an open research question): first FX column over the second over nothing, performance over both; a column keeps one FX (a note step replaces both, an FX-only step replaces a column that holds a voice FX or Off); the winner's change is a `ModSet` / `ModEnd` event, a change under an active winner is silent, both columns of a note step are applied together so that no transient shows. Engine FX (128..255) pass through, one group per column. Model-checked against a brute-force arbitration over 60,000 random operations.
- **Playheads and switching** (PAR-021): song cursor (order position, pattern, step), a cursor and a length per track (polymetric tracks wrap by themselves, all restart with the pattern; a Perform ping-pong track finishes its bounce first: its cycle of 2 L - 2 steps is longer than the pattern it is as long as, so it restarts only with a different pattern, or when a Break pattern, an Order jump, a live jump or a pattern switch cuts the pattern, OS-BUG-PERFPING; latent: after a Pause and Resume the track starts again at the resume row going forward, a phase jump, because the resume reloads every track from the row), pattern end by length, Break or Order jump; `queue_pattern` (the sequential switch: then Pattern mode), `request_mode` (Pattern ↔ Song) and the order list loop (`set_song_loop(false)` for an export), all at the pattern's end without stopping. **OS-PATSWITCH:** `switch_pattern` (command `SwitchPattern`, the held F1 chooser) is the one change that does not wait for the end: at the next step boundary the playing pattern becomes the chosen one and every track goes on at the same row (docs/specs/OS-PATSWITCH.md). Performance layer: per-track source pattern (switched at the track's own loop end, its FX ending there), length, play mode (forward, backward, ping-pong, random), stutter; tempo and pattern-length overrides; performance values.
- **Transport**: play_pattern, play_song, stop (note-offs, MIDI stop, `Stopped`), resume (from the step stop() left, with SPP + Continue), locate (the step number of an SPP; while playing, a jump at the next step), restart. The main loop reaches all of it through the command ring (`Sequencer::commands()`); the sequencer's ParamChanges are `seq_param::Tempo` (smoothed by the 005b `Smoother`) and `Swing`.
- **MIDI out.** MIDI-kind events (instrument kind Midi: notes on the instrument's channel, CC A..F, program change, clock, start / continue / stop, SPP) go through `midi::MidiOut`: due cycles from the sample (the clock to a fraction of a sample), per-port OUT offset, a sorted staging queue, hand-over to the ports' SPSC rings within two blocks. Hang bookkeeping (PAR-063): per channel and note the notes owed; a new note on a track ends the sounding MIDI note first whatever the new instrument is (our rule: a sample instrument after a MIDI note must not leave it hanging), Cut and Fade end a MIDI note, a muted track's MIDI note ends, a stop owes exact offs (a few a block, due after what the ports hold), an export suppresses MIDI.
- **The emitter** (`midi/din.h`, "clock is sacred"): real-time bytes go between the bytes of any message at the byte boundary, never wait for a SysEx or a CC burst; a byte is 57,600 cycles (320 µs); commit depth 1 (a byte is handed to the UART when the previous one has gone) makes the busy-wire bound one byte time, depth 2 two; the card's guard window (no ordinary byte starts in the byte time before a queued clock) is an option, off by the maintainer's decision. SysEx are runs of 3-byte chunks that start only when the whole run is in the ring; `request_flush` cuts a message (closing a SysEx with F7) and drops what was queued before.
- **USB out** (`midi/usb_out.h`): the first frame at or after the due time, 16 events a frame, real-time first.
- **Clock follow** (`midi/in.h`, `midi/clock_dll.h`): per-port parser (real-time bytes inside any message, SPP), stamps → time with the port's latency (DIN: one byte time, USB: 0.5 ms), Start / Continue take effect on the next clock, a second-order DLL after Adriaensen (maths only), started by a least-squares fit of the first 12 clocks, B = 0.5 Hz tracking (4 Hz acquire available), drop-outs up to 24 clocks inferred, a tempo that leaps re-acquires with the tick count kept, the output is the prediction so a placed microstep is never revised. The sequencer follows it (`set_follow`) on the microstep grid with the user's offset (a delay shifts; an advance reaches back one clock period at most), swing off, the clock out relayed.

**Figures** (host simulations; `O3OS_SEQ_REPORT=1 o3os_tests --test-case="din:*,clock dll*,usb out*,seq follow*"` prints them; 4080 cycles a sample).

### 005d-lite as built (2026-10-11): sampler voices, the sequencer in the render, transport, demo kit, "suena un patron"
The smallest version that plays a pattern correctly. Not the 005d of ADR 0013 D9 (that row, with its 8 play modes, envelopes, LFOs, modulation matrix, SVF, drive, span prefetch and the 16-voice pool with tails, stays open); this slice is its first floor, and nothing in it has to be undone for the rest.

**Where it lives.**
- `audio/voices.h`, `src/voices.cpp`: `VoicePool` (8 voices, the 64-slot `SampleDesc` table, one block a voice), `pitch_inc_q32`.
- `audio/event_source.h`: how the engine gets events, a plain record of two function pointers, because the audio layer may not include the sequencer. `seq/engine_link.h` builds one over a `Sequencer`.
- `audio/engine.h`, `src/engine.cpp`: `attach_voices`, `attach_events`, `play_block`, `dispatch`.
- `audio/graph.h`: `use_feed_sources` and `set_param_hook`, the two small hooks.
- `audio/demo_kit.h`, `src/demo_kit.cpp`: the four generated sounds.
- `model/demo.h`, `src/demo.cpp`: the four instruments and the two-bar pattern.
- App: `TransportSink`, `transport.play`, Play bound in `global`, the status strip's badge.
- Platform: `audio_voices()`, the composition root's sound (`app_main.cpp`), the opening of the outputs (`main.cpp`).
- Tests: `audio_voices_test.cpp` (host and QEMU suite `audio_voices`), `audio_demo_test.cpp` (host), a Play case in `pattern_edit_app_test.cpp`, two `static_assert`s in `audio_model_ids_test.cpp`.

**What a block does now** (`Engine::render_block`, when voices are attached). One `step(clock, 64)` of the event source, always, on a `uint64` sample clock the engine counts (an underrun mute included, so the timeline never skips); the voices render up to each event's sample offset, the event starts, ends or cuts its note, the rest of the block follows; `end_block()` hands each sounding track's block to the graph as its feed (`SourceKind::Feed`, every track); then `Graph::render`. Sample-exact: a note at offset 17 is silent through sample 17 and its attack begins at 17 (test: the voice block sample by sample, and the graph output exactly zero up to there). The ParamChanges the graph does not own are offered to the sequencer (`Graph::apply`'s default case, the 005c "not in this slice" hook): `seq_param::Tempo` and `Swing`. Note events (`NoteOn`, `NoteOff`, `NoteCut`, `NoteFade`, `Stopped`) drive the voices; `ModSet`, `ModEnd`, `FxReset`, `Tick`, the MIDI events and the UI's are ignored here (the MIDI out stage and the UI are other slices').

**Decisions.**
- **One voice a track, 8 in the pool.** A new note on a track takes that track's voice over where it stands. A note on a track with none takes a free voice; with none free, a voice that only holds a click's tail; with none of those, the oldest playing voice (age counter, wrap-safe). So with 8 voices a 9th sounding track costs the track whose note is oldest. No tail voices: one constant (`kMaxVoices`; a voice is 200 B of SRAM_U, 72 of state and 128 of block) and, for the D3 tails, the same table.
- **Pitch.** 12-TET against root note 60: the note table is 1.0 at index 60 (note 0 is 2^-5). A Q32.32 position increment from a 12-entry Q30 table (48 B) and a shift for the octave; relative error under 1e-8 for all 128 notes, octaves exact. Linear interpolation with a Q15 fraction; one shot or forward loop; a loop reads across its point and a one shot holds its last sample, so no guard sample.
- **No clicks, all linear, in samples.** Attack 32 (0.7 ms); NoteOff releases over 256 (5.8 ms); NoteFade over 13,230 (300 ms); an abrupt stop (a retrigger, NoteCut, the end of a one shot) leaves the voice's last output as a residual that fades to zero over 64 samples, so the output is continuous at every cut. A voice stolen by another track drops that track's tail (one click, only with more than 8 sounding tracks).
- **Velocity** 0..127 is linear (v / 127); the step's volume replaces the instrument's (open item V2); `kVelocityDefault` takes `SampleDesc::volume`.
- **Sample data** int16 mono in memory that outlives its notes (the sample arena); the table is the main loop's to fill before a note of the slot can start (boot, a loader). A slot is never rewritten under a playing voice: the loader slice has to silence the voices first.
- **Accounting.** The event source's cycles go to the report's Drain stage, the voices' to Render (`diag cpu` shows them).
- **The tone image is unchanged.** With `O3OS_AUDIO_TEST` the composition root builds no sequencer, voices or demo, and attaches no transport: the strips keep their test sources.
- **Outputs.** Every image boots muted. In the default image `main.cpp` opens them once, at boot (OS-OUTON; before it, the first press of Play asked for them, `appimg::audio_open_pending`): after the SD mount and the boot project load have ended (`mk66::open_wanted`, `platform/mk66/output_gate.h`: the codec's unmute blocks for 0.2 s with the display serviced and must not sit on the card's reads) and once the audio path has run clean for 0.6 s (the last 400 blocks without an underrun or a hardware fault, `OutputGate`: a fault earlier in the uptime, such as the SD card's first long read, does not count, OS-007g; the gate does not wait for the load by itself). They then stay open until power-off or a reset, so the amplifier key's click is the one at power-on and Play, Song Play and live notes never wait. The old request stays as the fallback: a Play, a Song Play or a live note that finds the outputs closed (the audio path came up late: `diag audio start` after a boot failure) asks for them, waits (`play: waiting for the outputs to open`) and starts when the same gate opens them. Every SYSRESETREQ drops the amplifier key first (`boot::reset_chip`; the `reset` command also mutes the codec; a fault handler does the key alone), and `fw update` mutes before its hand-over. The log (`diag log`) says `audio: outputs open, underruns N faults M` when they opened, and 1.5 s after every Play that reached the sequencer `play: steps ... notes ...` and `play: running ... missing ... torn ... lost ...`. A failed unmute is the tone image's fatal blink code; in the default image it is logged (`audio: unmute FAILED, failures N`), the LED shows the audio code and `diag stage` lists the audio fault while the display and the console stay up, and it is retried after 2 s, three times without anyone asking (`OpenRetry`), then only when a Play, Song Play or live note asks; a success takes the code back. `fw update`'s quiesce clears the "open" flag and the open is never made while the update path holds the card, so a hand-over that fails or times out opens them again afterwards. Stop does not mute again.
- **Transport.** `transport.play`, bound to Play in `global` (any screen can stop the music): stopped, it plays the pattern being edited (`view.edit.pattern`) from its first step in Pattern mode (loops); playing, it stops (note-offs, then the voices release). A `TransportSink` carries it (the device's puts a command on the sequencer's ring: the main loop is its one producer); with none attached (the simulator) the action is Disabled. The badge on the status strip (Pattern, Song, Params) says PLAY or STOP from `ViewState::playing`, the last request that went through.
- **Demo kit.** At boot, with no sample in the table and no instrument in the project, the composition root generates four sounds into the start of the sample arena (30,338 samples, 61 KB of SDRAM; about 1.5 KB of cold code, no data in flash): a kick (a sine falling from 180 to 45 Hz under a 140 ms decay), a snare (noise and a 180 Hz tone), a hat (noise through a first difference, 22 ms) and a bass (the first 8 harmonics of a saw, one cycle of a C at 130.8 Hz, looped), each normalised to its own peak: 0.40, 0.28, 0.15 and 0.20 of full scale, which add up to 0.998 (the pan law's centre is unity on both sides, tracks add, and the demo must not clip). Four sample instruments KICK, SNARE, HAT, BASS go into slots 0..3 and, if pattern 1 is empty, a 32-step pattern on tracks 1..4 (kick on every beat plus two ghosts, snare on 2 and 4, hat on every second step with accents, a bass line C2 C2 Eb2 / Bb1 Bb1 F2 each ended by an Off) at 120 BPM. Plain Project mutators before the document is attached: no undo unit. The generators are deterministic; the host test renders two bars twice and compares a hash.

## 005c2 — MIDI drivers on the MK66: DIN UART in/out, PIT-compare emitter, USB-MIDI binding
Builds on OS-006b.
- **DIN.** The UART runs at 31,250 baud. Its pins come from the board's pin map. Every RX byte is timestamped in the ISR into `midiRt`. TX is driven by the PIT-compare emitter, using the PIT channel that ADR 0013 assigns to MIDI out.
- **USB-MIDI.** The OS-006b MIDI rings are bound to the same timing core.
- **Clock behaviour.**
  - Clock out on DIN and USB, with per-port enable.
  - Clock in from a selectable port.
  - Per-port offset settings, as OS-002d parameters.
- **hw-session (HW-B).** Measure, against a reference device or a logic analyser on the DIN TX pin:
  - clock jitter on an idle and on a busy wire;
  - lock time and phase error when following an external clock;
  - Start/Stop/SPP behaviour.

### 005c2 as built (2026-10-12)
**Where it lives.** `midi`: `time_ref.h` (the cycle-counter to timeline map the interrupts share), `din_io.h` (the UART4 receive and PIT-compare transmit interrupts over a register policy), `usb_bind.h` / `src/usb_bind.cpp` (the USB endpoint's SOF and from-host steps), `config.h` (`MidiConfig`, `SyncStatus`, `SeqLockBox`). `seq`: `midi_link.h` / `src/midi_link.cpp` (`MidiLink`, `MidiLinkHooks`, `sync_config_from_settings`). Platform: `midi_config.h` (register facts, baud and tick arithmetic, static_asserts), `midi.h` / `src/midi_din.cpp` (UART4, PIT0, the two handlers), `usb/src/usb0.cpp` (`bind_midi`, the interrupt body), `audio_block_heard_at()`, `Pipeline::render_stamp()`, `board.h` `kMidiRx`, `resources.h` (PIT0 claimed), `app_main.cpp` (the link in the composition root). Layer rules unchanged: platform includes `midi` only; `seq` builds the link; `app_main.cpp` is the one file that sees both. Tests: `midi_io_test` (18 cases: time map, DIN RX and TX interrupts against a fake UART and one-shot timer including a fuzzed stream, the USB binding, the config clamps and the sequence lock), `seq_midi_link_test` (12: master on DIN and USB, ports, SPP + Continue, Stop and hang bookkeeping, OUT offset; slave lock, transport, relay, IN offset, followed port, a master that goes quiet, a mode change while following, the Play key under an external clock; the settings mapping and the config path), `mk66_midi_config_test` (5).

**The contracts** (each shared object has one writer and one reader; the full table is in `midi_link.h` and `platform/mk66/README.md` "MIDI drivers"). UART4 RX (48) is the one producer of the DIN `midiRt` ring, USB0 (64) the one producer of the USB `midiRt` ring and the one consumer of `UsbMidiOut`, PIT0 (96) the one consumer of the `DinEmitter`; the render (128) is the producer of the emitter and of `UsbMidiOut`, the consumer of both rings and the only writer of `TimeRef` (two slots and an index, release store; readers are above the writer). The main loop writes the configuration through a sequence lock the render reads without waiting. No interrupt allocates, blocks, prints or loops without a bound; the hot code is flattened into SRAM_L and `check_ramfunc` finds nothing new.

**What it does.** The DIN byte stream: RX stamps every byte (the interrupt's entry, the first thing it does), PIT0 is a one-shot armed for `DinEmitter::next_wake()` and writes one byte per entry at commit depth 1 (the next byte of a message at the end of the byte in flight, a clock at the next boundary: "clock is sacred" as in 005c). The render pends the line after it hands the ring anything. USB: the frame's events go into the to-host ring before the device logic arms the IN buffer, so they leave in that frame; from-host events become stamped bytes of the USB port. **Sync** (`MidiConfig::mode`): *Off*; *Master* (the sequencer's `emit_clock` on while a port is enabled, a Play begins one block later so SPP and Start go first; Start from step 0, SPP + Continue from anywhere else, Stop); *Slave* (the followed port's clock through the DLL, the sequencer's timeline the loop's with the port's IN OFFSET; Start, Continue, Stop, SPP move the transport; `out_ports` relays on the followed time). OUT OFFSET per port is the router's (cycles, exact); a Stopped event also asks the router to release what is still owed (PAR-063).

**New Community OS behaviour (not parity; each one branch, reversible):** (a) a master quiet for 48 clocks (two beats) while followed stops the transport and releases the loop; (b) the Play key under an external clock starts on the master's next clock, on its grid (`Sequencer::next_follow_clock`; before this a Play under follow started at clock 0 of the loop's count, in the past: 66 late events and 14 microstep overruns in the test, now none); PAR-122's count-in state machine is not specified and not built; (c) a change of mode or of the followed port stops the transport first; (d) the loop is attached to the sequencer while it is stopped, or at the master's own Start or Continue; (e) **the time base is the moment a sample is HEARD** (render boundary + the TX ring's render-ahead, one block), not the render's own time: MIDI out leaves with the sound and a clock in is placed where the sound of that instant is. The radar card's wording ("the cycle count stamped at that block's boundary") would put MIDI out and in one block (1.45 ms) off the audio; one constant (`midi_cfg::kAudioLeadCycles`).

**Settings.** The device file's CLOCK IN (Internal, USB, MIDI In jack) and CLOCK SYNC (PAR-119) are used: `seq::sync_config_from_settings` (Internal is a Master when a clock-out port is enabled, else Off; USB or jack a Slave on that port; the pulses are the correction), driven from `app_main.cpp` whenever either generation moves. **CLOCK OUT, the offsets, FOLLOW, the notes' ports and the CC numbers have no row in the settings table, so they are runtime values** (`midi::MidiConfig`, defaults: Off, nothing out, notes on DIN, CC unassigned), set by `appimg::set_midi_config()` / `MidiLink::set_config()`, clamped by `midi::sanitized`, lost at a reboot. Making them persistent is device-scope rows in `model/params.cpp` (fields 7.., `kValueBytes` has room for 9) and changes the settings file's golden (docs/formats/o3-settings.md section 8); that is the Config page's slice, with the radar card's own note ("version bump, older-version loader, round-trip test"), and was not made here. **API for the Config page:** `appimg::midi_config()`, `appimg::set_midi_config(const midi::MidiConfig&)`, `appimg::midi_status()` (`midi::SyncStatus`: following, clock_present, locked, bpm_x100, clocks, error_us, transport_events).

**Memory** (`-Os`, against the previous build, incremental mk66 build): flash +14,580 B (2,560 B of it SRAM_L code), `.data` +16, SRAM_U +21,736 B (`MidiLink` 21,728), SRAM_L +2,560 B (3.3 KB of the region free after it).
