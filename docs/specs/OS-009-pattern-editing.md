## 0. What exists and what this slice extends

Verified in the tree on 2026-10-11.
- **The Pattern screen** (`app/include/o3os/app/pattern_view.h`, `src/pattern_view.cpp`, `pattern_layout.h`, `src/screens/pattern_screen.cpp`): OS-001b, restyled in OS-003b, registered in OS-002b. It draws **static demo data** (`app::PatternData`: 12 tracks x 64 steps, an app-local `Step` with its own encoding) and cannot edit. The strip (PAT 03/12, BPM, LEN, JUMP, SONG), the track headers (`track_name`) and the info line ("scale A min ... undo 12/64") are placeholders. The cursor is (row, track, column) in a 16 x 5 window and implements the `Cursor` interface (count = 64), so `cursor.jump_fraction`, `cursor.jump_end`, `cursor.page`, `cursor.track`, `cursor.home`, `cursor.end` already work on it; Shift+F1..F4 = 0/4..3/4 and Shift+F5 = end are bound in Global (`nav_actions.cpp:56-66`, `bindings.cpp`).
- **Modes** `Edit / Follow / Select` (`pattern_screen.h`), one binding context each; `Select` is only "arrows page and change track" (a 002b placeholder, goldens `screens/pattern_select_mode`, `pattern_select_page`); `view.mode_next` = Shift+Rec. The context chain is overlay, mode, screen, global (`ContextChain::kMax = 4`, `core/binding.h`).
- **Actions that touch the pattern**: `pattern.column`, `pattern.fx_column`, `instrument.select` (a pad selects the instrument in every column). `edit.undo/redo` (F8, Shift+F8), `macro.*`, `project.tempo` (002c). Unbound today (`bindings.cpp`): Shift+arrows, Play, Copy, Insert, Delete, plain Rec (only Shift+Rec is bound), Shift+pad.
- **Model**: `model::Pattern` (16 tracks x 128 steps x 7 B, a length per track, a name), `Project::pattern(id)`, `Editor::{create_pattern, clear_pattern, set_step, set_steps, set_track_length, set_pattern_length, set_pattern_name, set_track, set_track_name}`. Journal (002c): 384 KiB, units and groups, a step edit is 48 B, a pattern clear 14,368 B. Settings (002d): the device block has 7 of 16 fields.
- **Does not exist yet**: scales and the pad board, the FX table, a clipboard, a selection, the Fill dialog, arm, PC-key input (`InputKind::PcKey` is reserved, no HAL, no keymap word), a modifier **set** (a gesture carries one `modifier` InputRef), a per-field binding context, a document attached by the platform (only the simulator's `document` command attaches one).
- **Budget today** (`o3sim --gallery`, limit 1792 words): pattern worst 1186 (VERTEX_TRANSLATE) and **1496 (fallback mode)**, typical 967/1125. The fallback mode binds: the whole slice has **296 words** of headroom on the Pattern worst case (allocation in section 3).

## 1. Decisions taken in this spec (veto possible)

- **D1 Document first.** The Pattern screen reads the attached document's pattern (`model.project->pattern(view id)`); without a document it shows today's demo, read-only, and every edit is Disabled with a "NO PROJECT" notification. So no existing no-document golden changes except the info line (D2). The platform attaches a fresh document at boot (`reset()`, pattern 1, one song position): the platform side is a few lines in each target and is listed in P1a.1.
- **D2 Edit is a mode.** Modes become `Edit` (0), `Follow` (1), `Select` (2), `Browse` (3): the ids of 002b stay, `Browse` is appended, and a new `Screen::default_mode` makes **Browse the default** (edit mode off: pads preview until Rec arms editing; this OS's rule). Rec (tap) toggles Browse and Edit (the official manual describes Rec as toggling editing, `docs/ui/official-manual-map.md`; not verified). Edit actions are `enabled` only in Edit and Select (F4, F6, F7, F8, Copy, Insert, Delete are unbound outside edit mode, this OS's rule; F8 undo stays available in Browse, as 002c made it); everything else is bound in the screen context. `Follow` keeps its 002b placeholder meaning until OS-005c (Q-P1-16).
- **D3 Field level in the chain.** Chain = overlay, **mode, field**, screen, global (`kMax` 5). A screen declares the field under its cursor (`Screen::field_context`): Pattern: `pattern.note`, `.instr`, `.vol`, `.fx` (FX1 and FX2 share one). Rule of thumb: a mode row overrides, a field row specialises the screen's default. A field change must **not** reset the gesture layer (the `sync_context` comparison ignores the field level), or moving the cursor would drop a held button.
- **D4 One rectangular selection** in `ViewState`, never persisted. Every edit action is selection-aware (single-step and multi-step branches); with no range the selection is the cursor step.
- **D5 Session state, not persisted** (as `og.md` treats it): edit step (default 1), the pad board (scale 0, offset 12, root 36), last used instrument/FX, piano octave, armed tracks, fill dialog data, clipboard. Q-P1-15.
- **D6 Mute and solo are undoable** edits of `TrackSlot.flags` through `Editor::set_track`, because that is the single choke point; Q-P1-12.
- **D7 Unequal track lengths** (the model allows them): steps past a track's own length are drawn in `Empty` and refused by every edit ("PAST TRACK END", info notification).
- **D8 Pure operations live in `model/pattern_ops.h`** (copy, paste plan, reverse, transpose, duplicate, expand, shrink, fill, Euclid): functions over `Step` arrays that mutate nothing; an action applies the result through `Editor::set_steps`/`set_pattern_length` inside its one undo unit. Randomness comes from an injected `core::Rng` (xorshift32); the simulator seeds it with a constant.
- **D9 FX picker:** only `Implemented` slots (and 37) are selectable; placeholders keep their data and stay inert (PAR-003). Flipping a placeholder when its row lands is one table row.
- **D10 Encoder undo granularity** is one unit per detent (this OS's first choice, since replaced by OS-UNDOGRP's groups; the official firmware's granularity is an open research question). Coalescing needs a journal feature (Q-P1-11).
- **D11 F-key meaning in dialogs.** The Fill dialog has its own labelled keys, F7 CANCEL and F8 APPLY; the generic "F8 = Back" of 002b yields to a dialog's own labelled keys.

## 3. Gates common to every sub-slice

- **Undo (002c).** Every action that changes the project is `kActionUndoable` (Disabled without a document) and is one undo unit named by the action and its argument. Compound operations (fill, paste, duplicate, expand, shrink, record note plus its off) are one unit; "the pattern does not exist yet" creates it inside the same unit. Each sub-slice extends the 002c property test (`undo_test.cpp`): random sequences of its actions with undo and redo against full `Project` snapshots. The PR also reports journal bytes per action and the depth after 20 consecutive worst-case operations (a whole-pattern paste is about 29 KB), asserts `damaged() == 0`, and checks that a macro of an edit run replays as one unit. Navigation, selection, modes and choosers are `ViewState`, not undoable.
- **Budget, three themes.** Every UI state is a `ScreenState` row (`sim/src/screens.cpp`, `screens_app.cpp`) measured by `budget_test` and `o3sim --gallery` in Amiga, Black and White and both translate modes: worst-case states at most 1792 words, others at most 2048. Allocation of the 296-word headroom of the Pattern worst case in fallback mode: P1a.1 at most 140 (selection at most 90, header marks 40, chips 10), P1b 20, P1d 60, the rest spare; each PR reports its new worst-case number per theme and mode. A new overlay uses the covered rectangle (OS-002b), so base plus overlay is one measured frame. P1e.1 adds whole states (horizontal typical and worst, compact), not Pattern headroom.
- **Sim goldens.** Each sub-slice adds one scenario (`pattern_edit`, `pattern_octamed`, `pattern_block`, `pattern_fill`, `pattern_record`, `pattern_pages`) with `snap`s and its `goldens.txt` lines; `--check --twice` passes. Existing goldens change only where the PR lists them, each looked at in all three themes after `update_goldens`; the maintainer views the gallery. New gallery states are named in each part.
- **Host tests.** Pure parts (ops, fill, Euclid, scales, FX table, pad board, LED model, text entry, keymap v2, modifier resolution) are host-tested with ASan/UBSan. Keep-exact behaviour is tested against the reference vectors in `tests/data/` where they exist (note, instrument and FX edits, clear, cursor, scales, pad board, insert and backspace); they are the output of our own reference model (maintainer, 2026-10-18) and pin this OS's behaviour, not the official firmware's, which stays an open research question; a rule with no vector there is covered by properties or hand-written cases. The OS result must equal the vector under the encoding map (note -1/n/-2/-3/-4 to 0/n+1/253/254/255, instrument i to i+1). Random fills compare on an injected identical draw sequence; the original firmware's random sequence itself is not reproduced.
- **MK66 and QEMU.** 0 warnings, sizes per library and the delta against the base in each PR; the pure model pieces get a QEMU suite as in 002c. Nothing here runs in an ISR or an audio `update()`; no heap.
- **Layers.** Pure ops in `model`, actions and screens in `app`, keymap machinery in `core`; `check_layers.py` passes; no colour literals.
- **Persistent formats.** No layout changes: patterns, tracks and names use existing fields. The only persisted additions are device settings in rows 7-9 of the device block (Keymap, Rec Quantization, PatternArrangement): per `o3-settings.md` a new row needs no version bump (default-fill); the document's payload sizes are updated and a settings round-trip test reads an old file. OG export is unchanged.
- **Reviewer** approves; the layer checker passes.

## P1a.1 — Edit core

**Scope:**
1. **Document-backed view (D1, D7).** A read-only `PatternSource` (track count, `track_length(t)`, `step(t, row)` as `model::Step`, the `TrackSlot`, `pattern_length()`), backed by the document or by the demo (the old `PatternData` converted cell by cell). `PatternView::draw`, `format_field` and `fx_type_char` work on `model::Step` (note byte per ADR 0004, FX type 0 = none). Wire the placeholders: strip PAT (id and count), LEN, JUMP, INS (instrument name); track header badge, number, name; **M, S and arm marks** in the header's badge row (arm in Accent: "orange is record-arm", style guide section 1); the info line shows the pad-board scale and root, the mode chip (`BROWSE` / `EDIT ON` / `FOLLOW` / `SELECT`) and the journal depth (`undo n`, no denominator: the `12/64` was a mock). BPM, SONG, CPU, the transport badge and the meters stay placeholders (P2, OS-005). `Cursor::count` = pattern length; tracks scroll up to `active_tracks()` (12 by default, at most 16). Platform: each target attaches a fresh document at boot.
2. **`ViewState::PatternEdit`**: current pattern id (1..255, default 1; a missing pattern shows empty and the first edit creates it in the same unit), edit step 0..32 (default 1), piano octave, last FX type, pad-board scale/offset/root, the selection. `Screen::default_mode`, the four modes (D2), the field level (D3), new contexts appended to `Context`: `PatternBrowse`, `PatternNote`, `PatternInstr`, `PatternVol`, `PatternFx`, `Chooser` (keymap names `pattern.browse`, `pattern.note`, `pattern.instr`, `pattern.vol`, `pattern.fx`, `chooser`).
3. **Selection (D4).** `Selection {active, anchor, rows, tracks}`. Actions `select.extend dx dy` (Shift+arrows: anchored where Shift was first pressed), `select.column_all` (Shift+Up at step 0: the column, again all tracks; **not available in Follow**, so a playhead passing step 0 cannot select everything: PAR-093), `select.clear` (any plain move or edit-cursor move collapses it), `select.mark` (toggles Select mode with the anchor at the cursor; the OctaMED block mark). Shift+Insert is HOME: collapses and jumps to step 0 (`cursor.jump_fraction 0`). In Select mode the arrows extend the block; the old coarse page/track rows of 002b are removed (goldens listed). Drawn as one `Sel` rectangle per visible row across the selected tracks (at most 16 rectangles).
4. **Edit actions** (`kActionUndoable | kActionNeedsFocus`, enabled in Edit and Select, selection-aware). Rule (this OS's model): a single step takes the single-step branch, several steps the multi-step branch.

| Action (arg) | Behaviour and source |
|---|---|
| `step.note` (model note byte) | pad and key entry. Single: an empty step takes the last-used instrument; multi: only steps that already have a note change (this OS's rule); then the cursor advances by the edit step when there is no range (wraps at the pattern end, does nothing for step 0). |
| `step.note_delta` (detents) | encoder in the Note column (this OS's rule). Single: an empty step with +: note 60 (model 61) and the last-used instrument; otherwise clamp in rank order Off < Cut < Fade < Empty < C-0..G-9 (the OG file's note values -4..127). Multi: only notes, clamp 0..127. Reserved bytes 129..252 are carried untouched (PAR-003 rule). |
| `step.note_octave` (+-1) | Shift+encoder (PAR-052): the same rule with +-12. Per-note clamp (Q-P1-4). |
| `step.instrument`, `step.instrument_delta` | an empty step gets note 60; the encoder walks the instrument order = slots 63..48 then 0..47 with the delta clamped to +-5, applied to slots, stored as slot + 1. NEW COMMUNITY OS BEHAVIOUR (OS-SHIFTENC): Shift + encoder is `step.instrument_coarse`, 8 places a detent with the clamp lifted to 64 places (the walk itself, and the plain encoder's +-5, are unchanged); `step.vol_coarse` is 10 a detent, `step.fx_value_coarse` 16, both through the same delta rules. |
| `step.vol`, `step.vol_delta` | the Vol column is OS-new (the OG has no volume byte, its volume is FX 18: `og.md` section 4). Same single/multi rule as an FX value; range 0..127, 255 = unset; the value on first entry is Q-P1-10. |
| `step.fx_type`, `step.fx_type_delta` | on the cursor's FX column; picker order `kPickerOrder` (`model/fx_table.h`), executable slots only (D9); leaving a non-executable type restarts at the new type's default. |
| `step.fx_value`, `step.fx_value_delta`, `step.fx_pad` | as the reference model (new Community OS behaviour; the official firmware's is an open research question): clamp to the type's min..max; on an empty FX slot, single: type := last-used, value := default; a non-executable type is untouched. `step.fx_pad` scales the pad 0..47 linearly onto the type's min..max in **integers** (new Community OS behaviour: the `kFxDigest` vectors of `tests/data/pattern_edit_vectors.h`, the output of our own reference model; for a type with the range 0..1, pads 0..23 give 0 and 24..47 give 1). Per-FX "Pad Range" table: Q-P1-9. |
| `step.clear` (element mask) | Note/Instr = note empty and instrument 0; FX = type 0. The OS writes (0,0) as the value byte: not observable (a None slot's value is ignored, `sanitize`). The default mask comes from the field: FX column clears that FX, the Vol column the volume, Note and Instr the whole step; then the cursor advances by the edit step and the Community OS stops at the last row, so a held Delete never clears from the top (new Community OS behaviour, OS-DELREPEAT, no parity claimed; what the official firmware does at the last row is an open research question). Clearing a track (select the column, Delete) empties it and **changes no length** (PAR-073 "pattern length when clearing tracks on 128-step patterns", a release-note item: documented, not verified) and always writes instrument 0, so no leftover MIDI instrument shows (PAR-093). |
| `step.insert`, `step.pull` | insert shifts the selected tracks down from the block's first row (the cursor's row when nothing is selected; maintainer decision 2026-10-22, OS-QAFIX-17: the cursor sits at the block's far end, the block's first row is what the user marked) through step 127 and clears that step (steps pushed past the length are kept); pull (OS-DELPULL, replaces the earlier backspace; new Community OS behaviour, no parity claimed) deletes that step and pulls the tracks up from there through step 127, clearing the last; the cursor stays. A track whose length does not reach that row is left alone. |

5. **Choosers.** `PatternChooser`: tap F1 toggles, hold F1 opens until release; encoder +-1, Up/Down +-1, pads 1..48 = pattern, Left/Right = the previous / next pattern the project holds, skipping unused ids (OS-QAFIX-6, new Community OS behaviour; it was a placeholder); constrained to 1..255. `ValueChooser` for F2 LENGTH (encoder +-1, Left/Right the defined values 1, 2, 4, 8, 16, 32, 48, 64, 80, 96, 128; pads scale linearly onto 3..191, then clamp to the last step index 127, so 4..128 steps; sets **all tracks**, `set_pattern_length`) and F3 JUMP (0..32, defined values 0, 1, 2, 4, 8, 16, 32; label "Step jump", PAR-092). Each is a strip over the info line (covered rect), modal, context `Chooser`; F1 again or F8 closes it. F4 FILL is P1c, F5 PREVIEW (`pattern.preview`) and F7 EXPORT (`pattern.export_selection`, P6) are **reserved actions** that post an info notification until their slices land; F6 INVERT is P1b (outside Edit it says TURN EDIT ON, with no block SELECT A BLOCK TO INVERT; OS-QAFIX-12).
6. **Pad board and scales.** `app/pad_board.h`: the pad layout (this OS's own, as `pad_board.h` says; whether it matches the official firmware's is an open research question; pad 0 top-left = the highest notes), pad-board setup from (scale, offset, root), `note(pad)`, `pads_with_note`; `core/scales.h`: the 40 scale definitions and names, `is_in_scale`. Rows 11 (Melo Min), 17 (Blues Maj), 23 (Todi), 36 (Gipsy) are the four PAR-073 names: P1a.1 first shipped them with other definitions, flagged unverified (Q-P1-1); OS-PTOOLS then set them to the standard definitions of the names (`scale_corrected`; new Community OS behaviour).
7. **Mute, solo, Shift layer** (maintainer decision). Shift + top-row pad (indices 0..11) = `track.mute`, second row (12..23) = `track.solo`, track = index mod 12; toggles `kTrackMute`/`kTrackSolo` through `Editor::set_track` (D6). While Shift is held, the key row shows the Shift caps (`0/4 1/4 2/4 3/4 END - - REDO`) through `Screen::soft_keys_shifted`, and the header marks are drawn bold. Pad rows 3 and 4 stay free (P1d uses row 3 for arm).
8. **FX table** `model/fx_table.h`: the 43 rows `Row {support, lo, hi, start}` (`kRows`), `kPickerOrder`, `row()`, `is_executable`, `is_random_eligible`, `sanitize`; the ids 0..42 are fixed by the OG file format, and `tests/pattern_edit_rules_test.cpp` holds the rows equal to the sequencer's ranges (`seq/fx.h`).
9. **Bindings** (device layer, `bindings.cpp`; `builtin_bindings_test` lists every Shift row again): Rec tap `pattern.edit_toggle`; F1/F2/F3 tap and hold (choosers); F4 FILL (P1c) and F6 INVERT (P1b) keep the 002b placeholder until their slice binds them in the screen context (then Disabled outside Edit/Select); Shift+arrows `select.extend`; Shift+Up `select.column_all`; Shift+Insert home; Insert, Delete, Shift+Delete (backspace); pads by field context (`pattern.note` pad `step.note` via the pad board, `pattern.instr` pad `step.instrument pad+1`, `pattern.fx` pad `step.fx_pad`, `pattern.vol` pad `step.vol` mapped 0..127); encoder per field, **explicitly** `nav.scroll` in `pattern.browse` and `pattern.follow` (D3: the mode row wins); Fx held + encoder (`hold_encoder`) `step.fx_type_delta`; Shift+encoder `step.note_octave` in the Note field; Shift+pad rows (item 7). In Browse a pad previews: `pad.preview` is a reserved action (the engine hook is OS-005; a fake in tests). **Interim:** FX type by pad and the element-masked variants (a held column button with Delete, Copy, Paste, Invert) need modifier sets and land in P1a.2.

## P1a.2 — Modifier sets, PC keys, keymap v2, the OctaMED keyboard layer

Maintainer request (2026-10-11): OctaMED-style per-view navigation and edit modes, complex mode-dependent key combinations that are easy to define for every view, quarter jumps, every old function kept. This part makes the binding system express them as **data**; the OctaMED layer is one preset on top.

**Design.**
- **Modifier sets** (core). A gesture carries the **set** of modifiers held when it was recognised; a trigger names the exact set. The app declares up to 16 in one table: bit 0 Shift (the device Shift button **or** a PC Shift key), bits 1-4 the column buttons Note, Instr, Vol, Fx, bit 5 Rec (for example "hold Rec, press Play"), bits 6-8 PC Ctrl, Alt, Gui. Rules: matching is exact; a **device** input falls back once to the empty set (the 002a rule: holding Shift never kills a plain binding); a **PC key never falls back** (a mistyped Ctrl+X must not type X); a modifier key produces no gesture of its own; a column button used as a modifier still fires its own tap at its press (select the column), so "hold Note, press Delete" is a Delete with set {Note}. `chord` and `hold_encoder` keep their own fields. Implementation hint: the trigger's `modifier` InputRef gains a 16-bit `mods` indexed by the table; `Binding` should stay 16 bytes by packing (gesture and `arg_from` can share a byte); every extra byte is 256 B of the 256-binding pool, reported in the PR. Context changes spare every modifier still physically down, not only Shift.
- **PC keys.** `InputKind::PcKey`, `id` = the USB HID usage (keyboard page 0x07, 0x04..0xE7), the number SDL scancodes already use and a USB host keyboard will produce; modifier keys are 0xE0..0xE7; `value` 1 pressed, 0 released. Gesture kinds Tap, Hold, HoldEnd, DoubleTap (no chord, no hold-encoder on PC keys); an encoder tap with PC modifiers held is allowed (Ctrl+encoder). No auto-repeat in this slice (the producer's job, PAR-066, basket 12). The simulator gets scenario verbs `key <combo> [count]` (tap: `ctrl+shift+c`), `keydown <combo>`, `keyup <combo>`; no HAL produces them on the device yet.
- **Keymap v2** (`o3keymap 2`; v1 files keep loading unchanged, tested with the v1 fixtures; the loader is still all-or-nothing and reports conflicts with both lines). New forms, all lines remain `context gesture trigger action [arg]` at heart:
  ```
  o3keymap 2
  [global]
  tap  shift+f1  cursor.jump_fraction 0   # modifiers in front of a button: the quarter jump
  tap  key:f1    ui.softkey 0             # a PC key: key:<name>, names are a table over HID usages (a..z, 0..9, f1..f12, enter, esc, space, minus, kp0..kp9, ...)
  tap  ctrl+key:z  edit.undo
  [pattern]
  tap  key:space   pattern.edit_toggle    # the screen's own context: every mode
  [pattern.note]                          # the field: the cursor is on a Note column
  row  step.key 0  key:z key:s key:x key:d key:c key:v   # row: the i-th input gets arg + i (the two-row piano is two such lines)
  [pattern.instr]
  tap  key:1       step.digit 1
  pattern.edit tap key:5 step.digit 5     # the v1 form, context first, is still valid anywhere
  ```
  `+` joins modifiers for tap, hold, holdend and double, and two buttons for `chord` (the gesture word decides, so there is no ambiguity). A `row` expands at load time into ordinary bindings (the pool counts the expansion). `core/keymap_format.h` writes a pool back as v2 text, and `parse(format(pool)) == pool` is a property test: that is also what basket 6's key-reference generator reads.
- **Modes and fields, the same table for every view** (documented in the style guide section 9, one paragraph and an example): a screen declares its modes (`Screen::modes()`, an enum plus a `ModeDef` row each), its field (`Screen::field_context`) and its Cursor; its rows are lines under `[<screen>.<mode>]` or `[<screen>.<field>]` in the preset text. No C++ to add a key. Where one key must differ by mode **and** field, the action's handler decides (for example the same pad previews or enters depending on the edit mode); where it differs by one of them, the context does.
- **The layer.** The OctaMED layer is the **preset** binding layer (user > preset > built-in is unchanged); the device layer is untouched, and a PC key has no built-in binding, so with no preset the PC keyboard does nothing. The preset is **text**: one embedded `constexpr char[]` (`app/data/octamed.o3km`, estimate 6-8 KB of flash) parsed into the preset pool, so the embedded default and an SD file (`/keymaps/*.o3km`, basket 15) share one parser and one validation, and a missing, corrupt or conflicting SD file falls back to the embedded text with a notification (ADR 0009 principle). The pool grows 64 to 256 bindings (+3 KB of RAM, reported).
- **Selection in settings.** Device setting `Keymap` (field 7, enum `DEVICE` default, `OCTAMED`; room for more presets), a row in `model/params.cpp`. `App::select_keymap(id)` and the action `input.keymap <id>` apply it; the app polls the setting's generation each pass (no observers). Its screen is the Config page (P3); until then the action and the settings file reach it. Existing files read as `DEVICE` (default-fill).
- **New actions of this slice** (OS-new, keyboard-driven, behaviour [P]): `step.key n` (semitone n above the piano octave: note = octave*12 + n + 1 through `step.note`; in Browse it previews, reserved), `pattern.octave +-1` (the piano octave, 0..9), `step.digit n` (shifts a digit into the field under the cursor: decimal in Instr, hex in Vol and the FX value, the field's range applied after the second digit; undoable like any step edit), `input.keymap id`. Each gets a table test.
- **Seed content** (the structure is fixed by this spec, the key choices are **[P], proposed, not sourced**: the exact OctaMED SoundStudio key table must come from its manual, which the radar card leaves for research; the seed is the ProTracker/FastTracker/OctaMED convention and is replaced row by row when the table is sourced, Q-P1-14): piano rows (lower row z s x d c v g b h n j m, upper row q 2 w 3 e r 5 t 6 y 7 u, each continuing one octave on the next keys) in `pattern.note` as `step.key`; hex digits in `pattern.instr`, `pattern.vol`, `pattern.fx` as `step.digit`; octave down/up (`pattern.octave`); arrows, `shift+arrows` (`select.extend`), page up/down (`cursor.page`), home/end; `shift+f1..f5` quarter jumps and end (maintainer decision); f1..f8 as the soft keys; Space toggles edit; Delete, Backspace, Insert as the device's; Ctrl+Z / Ctrl+Shift+Z undo and redo. The `f6..f10` jump reservation of 002b collides with PC F6..F8 as soft keys: the preset binds the jumps to Shift+F1..F5 only (Q-P1-13). Song and Instrument get their navigation rows too, so the mechanism is exercised outside Pattern.
- **Held-button combos** (built-in device rows, now expressible): Delete with Note, Instr, Fx held = clear that element (this OS's rule); FX type by pad with Fx held (`step.fx_type`); Shift+Copy = paste and Shift+Delete = backspace unchanged; the variants for Copy, Paste and Invert land with P1b.

**Tests:** modifier-set resolution tables (exact; device fallback; PC no fallback; Ctrl+Shift+X vs Ctrl+X vs X; release in either order; a modifier alone gives no gesture; a column button as modifier plus its own tap; every held modifier survives a context change); keymap v2: every grammar form, every error (unknown key name, unknown modifier, a `row` that overflows the pool, a conflict inside a `row`, BOM, NUL), v1 fixtures unchanged, all-or-nothing, `parse(format(x)) == x`; the preset: loads with 0 errors and 0 conflicts and reports its binding count; **completeness** (a test fails when a registered `pattern.*`, `step.*`, `block.*`, `select.*`, `track.*`, `cursor.*` action has no preset row and is not in the explicit `kUnkeyed` list, and when a screen with a Cursor lacks the navigation rows), so each later slice adds its rows in its own PR; a **resolution table** in `tests/data/octamed_resolution.txt` (`<chain> <gesture> -> <action> <arg>`) covering one key in different modes and fields (`z` in Note/Edit and Note/Browse, a digit in Instr/Vol/Fx, Delete in Note and Fx, Space in Browse and Edit); the setting: round trip through the settings file with default-fill, the poll applies and clears the preset, a bad SD text leaves the embedded preset active with a notification; PC events through `App`: Ctrl combinations never leak a plain binding; the scenario `pattern_octamed.txt` (select the preset, enter a short melody with piano keys in Edit, digits into Instr, quarter jumps, undo).
**Gallery:** the info line gains a `KBD` chip when a layer is active (covered by the pattern worst case; state `pattern_kbd`).

## P1c — Fill dialog

**Scope:**
- **Generators** in `model/pattern_ops.h`, with this OS's rules, following the release notes and the official manual (documented, not verified):
 - **Step rule** (the rules the official manual lists, extended; not verified): NOTE (-4: steps that have a note), NO NOTE (-3), FX (-2: for Note and Instr fills either FX type non-zero; for an FX fill that slot's type), NO FX (-1), RANDOM (0), EVERY n (1..32: `offset % n == 0`, maximum edit step 32), and the new **EUCLID events (1..32)**.
 - **RANDOM density**: under the RANDOM rule this OS selects roughly 3 steps in 10 (new Community OS behaviour; the official firmware's rate is an open research question, not measured on the unit). The 1.3.0 "density" setting is read as the chance of a step being selected; range 0..100 % and default 30 are [P], new Community OS behaviour (Q-P1-3).
  - **EUCLID**: hit k of E over the N selected steps lands on offset `round(k*N/E)` (the catalog: "events 1-32 over the step range, rounded to nearest step"), computed in integers as `(2kN + E) / (2E)` (half up, [P]); E is clamped to N. Euclid is a **step rule** and the fill type supplies the values; both readings are [A] inferred from the catalog sentence and need Q-P1-2.
 - **Fill type**: VALUE (`from`), RANGE (`from` to `to` along the selection, descending allowed), RANDOM (between `from` and `to`, swapped if reversed). Linear note and instrument values are interpolated in integers (truncating), FX values in float and truncated to a byte (parity with the original firmware 1.1.14 is an open research question: no recorded vectors of the fill exist in the repository). A one-step selection gives `from`.
 - **Targets**: Note (+ scale: `is_in_scale`; an empty step gets the last-used instrument, and 80-83), Instrument (an empty note becomes 60; range 0..63 in the OG file, slots 1..64 here), Vol (OS-new, 0..127), FX1/FX2 (type = picker choice, or **random per step**: id in 2..40, retry up to 100, executable and neither Tempo nor Break Pattern, `is_random_eligible`; value clamped to the type's range; a non-executable type is refused, and 205).
 - **PAR-150 rule** (our rule for the case where a fill's in-scale search runs past note 127): a fill never writes outside 0..127 and never leaves a selected step with fewer fields than before; if no in-scale note exists between the mapped note and 127 the step is **left as it was** [C], Q-P1-1b. Random notes: at most 101 draws (new Community OS behaviour); the last draw is kept only if in scale, otherwise the step is left as it was.
- **Fill overlay** (F4 FILL in Edit and Select, modal, covered rect): fields STEP RULE, TYPE (VALUE, RANGE, RANDOM), FROM, TO (hidden for VALUE), PARAM (SCALE for Note, FX TYPE for FX, none for Instr and Vol), DENSITY (rule RANDOM), EVENTS (rule EUCLID), and a line "n/N STEPS" (how many steps the rule selects: OS-new, makes Euclid usable). F1..F6 select a field and pressing the selected field again steps its list with roll-over; arrows and encoder change the value; pads set it (note from the pad board, instrument = pad, FX = the pad scaled onto the type's min..max, as `step.fx_pad`); F7 CANCEL, F8 APPLY (D11). The dialog data persists per target column for the session (this OS's rule). Apply = one undo unit. The target is the cursor's column, the range the selection.
- **Scale list**: the 40 names on the PARAM field; the four corrected rows (Q-P1-1, closed by OS-PTOOLS) show the standard scales.

**Tests:** every fill kind with an injected draw sequence, by hand-written cases (no recorded vectors of the original firmware: open research question); **properties** (over scales, roots, ranges, rules): PAR-150 (the count of steps with a note never drops, no write outside 0..127, nothing outside the selection or the rule changes, unselected steps are byte-identical), PAR-073 (each selected step is written at most once, `EVERY n` selects exactly ceil(len/n)), PAR-093 (a Slice FX fill spans the type's 0..47 inclusive at both ends); density: over 10,000 seeds the hit rate is within 2 points of the setting and the same seed gives the same result; Euclid: for E <= N the number of hits is E, spacing is within +-1, E = N fills every step; the three manual vectors (8 steps, 4, 5 and 7 events) are **pending** (Q-P1-2): the row PAR-053 stays "partial" in STATUS until they are in the test; scales: all 40 rows against `scales.h` except the four flagged, flagged rows asserted flagged; dialog: roll-over, "To" hidden for VALUE, no redraw when nothing changed (PAR-104: counted frames), Apply and undo exact (undo property).

- **Reserved (Strategy B, no invented behaviour):** device setting `PatternArrangement` (field 9, enum `VERTICAL` default, `HORIZONTAL`, `REVOLVER`): the page the Pattern button opens first; `REVOLVER` (PAR-123, manual sec 3.7, text not in the repo: Q-P1-7) is a reserved value that is **refused**; "Pattern top info" (release notes) is a reserved enum value with no UI (Q-P1-8).
- **Hold Pattern: the pattern chooser** (PAR-015). Hold Pattern (400 ms) opens the P1a.1 chooser (the screen's `hold` row beats Global's, which keeps a slow press working on other screens), pads 1..48 select a pattern, the release (`hold_end`) closes it. 
- **Pad LED model** (`app/pad_leds.h`, pure: state and project to 48 levels Off / Back / Front through `pad_palette`): this OS's rules: chooser: the current pattern if it is 1..48, **occupied patterns** (any non-empty step, cached per `pattern_generation`) while Pattern is held; length place: the pad is the length scaled linearly from 3..191 onto 0..47; jump place: pad = edit step; Edit and Note column: the pads whose pad-board note is the cursor's note (`pads_with_note`); Instr column: the pad of the instrument if 0..47; FX column: the pad of the value scaled linearly from the type's min..max onto 0..47 (float, rounded to nearest) or the type's picker index while Fx is held. While Shift is held: pads 0..11 = muted tracks, 12..23 = soloed, 24..35 = armed (OS-new: feedback for the bindings of P1a.1 and P1d). The platform feeds the levels to the LED driver; no new hardware behaviour.
- **Labels.** MIDI instrument slots show `M01`..`M16` (PAR-104, a release-note item about the Horizontal-mode label); one `number_text(value, base)` helper formats pattern, step and instrument numbers, decimal now (P3 flips it to hex for PAR-120 and tests PAR-104's hex off-by-one there).
- **Refresh** (PAR-093): every page redraws after any edit or undo, keyed by the pattern's generation.

**Tests:** `HorizontalLayout::fits` in all themes; transposed-cursor table (the four arrows and the jump actions give the same (step, track) moves on both pages modulo axis); the **same-bytes property**: one random action sequence run on page 1 and on page 2 gives identical `Project` bytes; mask rules (at most two, add/remove, reset); LED model tables for every state above; `occupied(id) == any non-empty step` and the cache invalidates on edit and undo; `REVOLVER` refused, `PatternArrangement` default-fill and round trip; label table (`M01`..`M16`); horizontal redraw after an edit (frame hash changes) and none without one.
**Gallery and goldens:** `pattern`: `horizontal_typical`, `horizontal_worst` (12 tracks, 16 steps, two kinds per cell, swept over cursor), `columns_mask`; overlay `pattern_chooser_hold`; scenario `pattern_pages.txt` (cycle pages, edit on page 2, quarter jumps on page 2, the mask, hold Pattern and pick a pattern with a pad).
**Done when:** the above, gates of section 3, reviewer approval. Estimate 2.6k lines.

## P1e.2 — Names page and the text entry

**Scope:**
- **Page 3** (PAR-135): rows "PATTERN n NAME" (30 characters, `kPatternNameMax`, the PAMD limit) and "TRACK n NAME" for tracks 1..12 (20 characters, `kTrackNameMax`; the OG project file holds 8 names of 20 characters); an empty name falls back to the default. Edits through `Editor::set_pattern_name` and `set_track_name`, **one undo unit per confirmed name**, not per character. Names show in the track headers, the chooser and the strip. The Export note (names of slots 9-16 are cut to 7 characters, `og.md` section "Export") is shown on the row.
- **`TextEntry`** (a modal overlay and a pure state machine, reusable by File and Instrument naming): pads are characters on the on-screen keyboard of the official manual (§1.6; a table `kTextPadLayout[48]`; backspace and caps pads; the limit is the field's here, and whether the official firmware limits a name to 32 characters is Q), the encoder moves the cursor or picks a character, F-keys BACKSPACE, CAPS, ACCEPT, CANCEL. ASCII 0x20..0x7E only. The random-name key of the official manual (§1.6) is a **reserved key** (the OS has no name generator yet).
- **PC keys** type into it: printable keys are rows in the OctaMED preset under `[text]` (the field level in use: completes the PC-keyboard story outside note entry).

**Tests:** the text-entry state machine (insert, backspace at both ends, per-field limits 30 and 20 enforced, caps, cancel keeps the old name, non-ASCII and NUL rejected, cursor clamps); one unit per name and undo exact; name round trip through the native format and through Export to OG (OGPN, PAMD 30 characters; slots 9-16 cut at 7 and counted); PC typing resolves in `[text]` only; a hostile 64-character paste is clipped.
**Gallery and goldens:** `pattern`: `names_typical`, `names_worst` (30-character names); overlay `text_entry_typical`, `text_entry_worst`; scenario `pattern_names.txt`.
**Done when:** the above, gates of section 3, reviewer approval. Estimate 1.5k lines.

## 4. Out of scope

Song and arrangement editing (P2), the transport, sequencer, quantiser, preview sound and metronome (OS-005c; P1 leaves `pattern.preview`, `transport.rec_start`, `pad.preview` as reserved actions that notify), MIDI input and CC mapping (P4), export of a selection to a file (F7, P6), the sample editor, the key-reference generator (basket 6; it reads the preset text), SD keymap loading (basket 15; P1a.2 only fixes the hook and the fallback), hex numbering and Config pages (P3).

## 5. Order, dependencies, parallelism

`P1a.1` then `P1a.2` (needs the action names) then `P1b` (needs held-button variants) then `P1c` and `P1d` (independent of each other: different files, each adds one line to the action registry and `bindings.cpp`) then `P1e.1` and `P1e.2` (P1e.2 can follow `P1a.2` and `P1b` alone). External: OS-005c is needed only for the engine-side acceptance of P1d (live recording on a unit); everything else is host- and simulator-complete. Total about 15.9k lines over seven changes.

## 6. Open questions (not built until answered)

Each default is what the slice ships if nobody answers.
- **Q-P1-1 Scales (PAR-073).** The four named rows (Melo Min 11, Blues Maj 17, Todi 23, Gipsy 36) are the four PAR-073 names (a release-note item: documented, not verified). Closed by OS-PTOOLS: the standard definitions of the names, no parity claimed (new Community OS behaviour). **Q-P1-1b** the rule when no in-scale note exists below 127 in a fill (default: leave the step as it was; H-1).
- **Q-P1-2 Euclid (PAR-053).** Tie rounding, rotation, E > N, and the three 8-step vectors of manual sec 5.6 (not in the repo). Default: half up, no rotation, E clamped to N, Euclid as a step rule. Wanted: the vectors.
- **Q-P1-3 Density.** Range, default and meaning (default: percent chance a step is selected under the RANDOM rule, 30, our choice; the official firmware's rate is an open research question).
- **Q-P1-4 Octave transpose clamp.** Per note or the whole block; Shift+Jog on a single step. Default: per note (our choice; what the official firmware does is an open research question).
- **Q-P1-5 Duplicate, Expand, Shrink, whole-pattern paste.** Whole pattern or selection, overflow past 128, odd lengths, which parity Shrink keeps, whether a pattern paste carries the name. Default: section P1b. Manual sec 4.2.
- **Q-P1-6 Arm.** Persistence, where the control lives, behaviour with no track armed, tracks 9-12 (MIDI). Default: session only, Shift + third-row pad, none armed = all armed.
- **Q-P1-7 Vertical revolver (PAR-123).** The manual's sec 3.7 paragraph. Reserved and refused.
- **Q-P1-8 PAR-074 options.** The arrangement and "Pattern top info" option sets. Reserved.
- **Q-P1-9 Per-FX pad ranges (PAR-117, manual "Pad Range").** Default: the linear integer `map` for every type (our choice).
- **Q-P1-10 Volume column.** First-entry value and mapping against FX 18 (a default of 0 for FX 18 would make a freshly entered value silent). Default: 127.
- **Q-P1-11 Undo of encoder sweeps.** One unit per detent (this OS's first choice, since replaced by OS-UNDOGRP's groups) against coalescing, which needs a journal feature (merge into the open unit): maintainer decision plus a 002c follow-up.
- **Q-P1-12 Mute and solo in the history.** Default: journalled. Keeping performance toggles out needs a non-journalled mute bank in the model.
- **Q-P1-13 F6..F10.** 002b reserved them for the jump actions in the keymap format; PC F6..F8 are soft keys. Default: jumps on Shift+F1..F5 only.
- **Q-P1-14 The OctaMED key table.** The exact keys of OctaMED SoundStudio from its manual (radar card: research later); the seed is [P] convention. Key repeat is PAR-066.
- **Q-P1-15 Persistence of session values** (pad-board scale, offset, root, edit step, last used): session (as `og.md`) or project settings.
- **Q-P1-16 Follow.** With edit off, the cursor follows the playhead while playing and the encoder does not scroll (this OS's model; what the official firmware does is an open research question); keep `Follow` as its own mode or make it Browse's playing behaviour. Decided with OS-005c.
- **Q-P1-17 Shift + pad.** The product-ux "select without sounding" against mute, solo and arm on rows 1-3; row 4 stays free.
- **Q-P1-18 PAR-155.** The 1.9.1 OFF placement and the "Only Notes" option (our default is only notes). [C], with OS-005c.
- **Q-P1-19 The sharps of the tenth octave.** Notes 121..128 would be written "C10" "C#10" "D10" "D#10" "E10" "F10" "F#10" "G10" ; a note tile is three characters. Default: the plain spelling for the five naturals, a lowercase letter for the three sharps ("c10" "d10" "f10"); the alternatives are a hex octave for all of them ("C-A", "C#A") or a wider note column (the grid is a whole number of 10 px cells and 5 tracks fill 800 px, so it would cost a track or the cell gaps).
