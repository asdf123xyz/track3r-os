# OS-FILES part A: import MOD / S3M / MED from the File screen

Status: spec 2026-10-14 · Level B · **new Community OS behaviour** (no historical parity claimed) · no persistent format change · every choice below is reversible (UI and glue only; the importers, `docs/formats/mod.md`, are untouched). Not in this slice: delete, rename, recents, purge, export (rest of OS-FILES).

## Choices

1. **Entry: File > F6 `IMPORT`** (the planned IMPORT page of `docs/design/product-ux.md` section 4). F6 toggles the page (label `PROJECTS` on the import page). The import page browses the card from its root (`DirScan` with `kModuleFilter`: every folder, and the files ending `.mod .s3m .med .mmd0 .mmd1 .mmd2 .mmd3`, any case, hidden names skipped). The test set sits in `/MOD /S3M /MED`. Keys there: F1 `ENTER` on a folder / `IMPORT` on a file, F2 RESCAN, F3 `UP`, F4 SAVE, F5 SAVE AS (unchanged), F6 `PROJECTS`, F7 `FX <engine>`, F8 `REPORT` / `LIST`. The format column says `MOD S3M MED` (by extension; the importer decides by signature).
2. **What it does:** replaces the document with a new unsaved project made from the module (the same hand-over as OPEN and NEW: transport stopped, voices let die, sample memory emptied). The importer starts only after that hand-over (its first act resets the project, which the render still reads until the Settle ends); `ModuleImport::begin` only checks the path and opens the file. **Failure:** a file that will not open (not found, card error) leaves the document and the sounds as they were; any failure after the importer began (bad signature, cut-off header, truncated body, overflow) leaves an EMPTY valid project and the voices' sample table and the bank are emptied with it. The result is a document marked unsaved (a second IMPORT and F3 NEW ask first) until a project save ends well. Project folder: none (`""`), so SAVE has nothing to replace; SAVE AS names it. The song name comes from the module header, the file name is only shown in the strip. The PCM goes straight into the sample arena (no `samples/instrNN.wav` is written until the user saves; the bank marks the samples as not on the card).
3. **Guard:** F1 on a file with changes no save has taken asks first (`UNSAVED CHANGES: F1 AGAIN TO DISCARD THEM`), the second press goes on; a move, another key or leaving the screen takes the question back. Same mechanism and flag as F3 NEW (`FileView::confirm_new`). OPEN (F1 on the project page) has the same guard since OS-OPENGUARD (same flag, same text, taken back the same ways; it asks only when the cursor is on a project folder; QA-FIL-012).
4. **Engine choice (F7 cycle, session memory, not saved): `FX AUTO` (default) / `FX AMIGA` / `FX MODRN`.** It is `ImportOptions::engine_fx` (`Auto / On / Off`; for MED `engine_fx` on / off): where the song's commands are written. AUTO = what the module is (MOD and MED to the Amiga engine window, S3M to the OG / core FX of the Modern engine). AMIGA and MODRN force it (e.g. a MOD as core FX to compare). The instruments keep what the importer gave them (Paula-rate MOD / MED samples play on the Amiga engine by rate; S3M on the Modern engine). The report names the engine used.
5. **Report:** the strip says `IMPORTED <NAME>` (+ `: F8 REPORT` when drop groups are set or samples did not fit, with `N NO ROOM, ` before it when samples did not fit) or `IMPORT <NAME> FAILED: <REASON>` (reasons as the importers' errors: `UNKNOWN FILE TYPE`, `TRUNCATED`, `DAMAGED FILE`, `TOO BIG FOR MEMORY`...). **F8 `REPORT`** shows a page (replaces the list until F8 `LIST`): format and channels, engine, patterns / order / tracks kept / dropped, instruments made / samples loaded / no room, `EFFECTS` approximated and dropped (counts), values clamped, and one line per dropped group by name (`drop_group_name`: "slide timing", "loop point", ...). It keeps the last import until the next one; it is not saved.
6. **Memory limits:** a song that needs more patterns or order entries than the model holds is refused whole (`Overflow::Refuse`; the project is left empty, as for any failure after the importer began) with `SONG NEEDS MORE PATTERNS THAN A PROJECT HOLDS`; the `Structural` / `Truncate` retries are a follow-up. Samples that do not fit the arena leave their instrument silent (as a project load: `no_room`, counted, the report and the strip say how many); more than 63 instruments / channels beyond 16 are the importers' own counted drops.
7. **Progress / jobs:** the import is a platform load, not an `ImportJob`: it needs the whole document and the sample memory, so it runs as phases of the project load (Settle, Import, Samples, Modules; `kLoadBytesPerPass`, the app's frames held, the strip says `IMPORTING <NAME>...`). `app::ModuleImport` steps the reader (bounded cells per step, each card read of the window counting as 128 cells so that a hostile MMD of jumping offsets cannot make a pass long, though one importer tick is not split; the module is read through a random-access source over the card) and then feeds the PCM into the arena in chunks (`OgSampleLoader::begin_feed`). No heap, no real-time path. Not cancellable (the document is being replaced).

## Memory and cost

`ModuleImport` holds the MOD/S3M importer (about 26 KB) and the MED importer (about 13 KB): main loop only, so it lives in the SDRAM slack window (`SdramBox`), not SRAM. SRAM: the view state (browse folder, 3 flags). Flash: +47.9 KB measured (the MED importer 24 KB, MOD / S3M 14 KB, glue and screen 9 KB); SRAM 0; SDRAM slack +40.8 KB of 192 KiB.
