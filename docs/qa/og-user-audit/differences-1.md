# OS-QANET E2, part 1: what the OS does against the owner's expectations

How it was made: an AI agent took each item E-<SCREEN>-NN of `expectations.md` for Sample Load, File, Sample Play, Instrument, Sample Edit and Sample Record and looked up what this OS does. Sources, in order: `build-map/keys.md` and `screens.md` (from `tools/code_map.py`), `docs/qa/catalogue/<screen>.md`, `docs/ui/ui-map.md`, the user manual chapters (they cite the catalogue), the handler code and the host tests it read. Nothing was run: no simulator, no unit. Every "static read" below is a reading of code, not an observation. The official manual and web pages were not read. No code or other file was changed.

Every row is an `open research question` for the maintainer. No row says the OS is right or wrong, and none claims parity. Severity: blocker (data loss, a silent destructive action, a stuck state), major (a main workflow broken or undiscoverable), minor (a habit that differs).

Counts (105 items): MATCH 61, DIFFERENT 35, MISSING 7, UNKNOWN 2. Blocker 2, major 6, minor 36.
