# OS-QANET E2 (part 2): what this OS does against the owner's expectations, Pattern, Song, Mixer, Perform, Config, Global keys and transport

How it was made. An AI agent took each expectation item E-PAT-01..38, E-SONG-01..11, E-MIX-01..07, E-PERF-01..08, E-CFG-01..07 and E-GLOB-01..18 of `docs/qa/og-user-audit/expectations.md` and looked up what this OS does. Sources, in this order: `build-map/keys.md` and `build-map/screens.md` (from `python3 -I tools/code_map.py`), the QA catalogue rows (`docs/qa/catalogue/{pattern,song,mixer,perform,config,global}.md`), `docs/ui/ui-map.md`, the manual chapters of this repository (`docs/manual/`), then the handler code (`app/src/actions.cpp` enabled predicates, `app/src/pattern_actions.cpp`, `step_actions.cpp`, `model/src/step_edit.cpp`, `app/src/app.cpp`, `seq/include/o3os/seq/midi_link.h`, `hal/include/o3os/hal/leds.h`, `core/include/o3os/core/gesture.h`). The official Polyend manual and web pages were not read. Nothing was run: no simulator, no unit. Every row is an `open research question` for the maintainer; no row claims parity, and no row says the OS is right or wrong on product grounds.

Counts (89 items): MATCH 56, DIFFERENT 28, MISSING 2, UNKNOWN 3. Severity of the 30 DIFFERENT and MISSING rows: blocker 0, major 4, minor 26.

Severity rubric used. blocker: loss of user content (patterns, samples, projects), a silent destructive action on such content, a stuck state with no way out. major: a main workflow broken or undiscoverable, or a final (no undo) silent reset of settings or routing, or a bounded stuck state. minor: a habit that differs. UNKNOWN rows carry no severity.

Findings outside the items:
- QA-PAT-126, 135 and 138 say a plain `Play` on Pattern plays "the song". The handler (`app/src/pattern_actions.cpp:215-237`, `transport_play`) calls `transport->play(edit.pattern)` on every screen but Song (the song, from the selected slot, only on Song). The catalogue wording and the code differ; the code was used here. A simulator run would settle which is meant.
- QA-PAT-150 says the song stops by itself at its end in LIVE; `seq/include/o3os/seq/sequencer.h:189` has `song_loop = true` and only the offline export sets it false (`seq/src/offline.cpp:121`). Live playback loops (used for E-SONG-05).
- `build-map/keys.md` lists `Pattern | tap Insert +Shift` as `cursor.jump_fraction 0`; `app/src/bindings.cpp:329,466` confirms it is HOME (step 0), not a bug of the generator.
