## Safety

- Install only after the maintainer's go, only a gate-checked image (`CANDIDATE.md` says PASS), only through the documented update path: the `diag` console updater (`platform/mk66/tools/o3console.py --put FILE.ptf`, then `--update NAME --crc X --yes-update --expect-volume XXXX-XXXX`) or a copy to `Firmware/` of an SD card (any SD card may be written: OS-ANYCARD, maintainer 2026-10-17, which replaced the test-card marker rule this session began with). The reset button flashes the first `.ptf` in `Firmware/`: list what is there before you copy.
- Never SWD or a debug probe, never a fixed or system disk or any other storage device that is not an SD card (OS-ANYCARD: no test-card marker is needed).
- Recovery: v0.5.0 is in `build-images/v0.5.0/`.
- Before any `reset` or long export: save the project (File F4). After hours of uptime injected holds may stop firing on old images; a software `reset` fixes it (OS-BUG-HOLD is fixed from v0.6.0 on: note whether it still happens).
- Project `Projects/t-v16` on the unit had instrument 1 VOLUME changed to 50 in RAM by the last session: reload it, never save it without checking.

## Checklist (v0.6.0)

Each row: do it, capture the evidence (console log, `shot` PNG, a short USB audio capture where sound matters), mark PASS / FAIL / NOT RUN with one line. QA ids point to `docs/qa/catalogue/`.

### Pattern (PAT-UX, REC-FLOW, PAT-NAV)
- [ ] OS-RECSIGN: the REC top sign and screen-edge border show in STEP, stopped and playing.
- [ ] OS-DELREPEAT: a held Delete repeats and speeds up like the arrows and stops at the last row; a single Delete on the last row stays there (new behaviour, confirmed). On PROJECTS a held Delete marks one folder only.
- [ ] OS-ROWWRAP: Up on row 1 goes to the last row and Down on the last row to row 1 on a fresh press; a held arrow stops at the end.
- [ ] OS-PADHOLD: in edit, a pad on the Instr column writes the note and leaves the instrument; the instrument changes only with the Instr hold popup or the encoder.
- [ ] OS-BUG-STEPSND: in STEP a pad sounds, stopped and playing (also over a track with a note on every step), on a sampler and on the TB-303.
- [ ] OS-PATCOPY: Copy / Shift+Copy of a block and of one step; paste clipped at the pattern end; one F8 undoes the paste; paste while the pattern plays over several tracks (listen for a glitch).
- [ ] OS-DELPULL: Insert then Shift+Delete gives the pattern back; the cursor stays.
- [ ] OS-COUNTIN: count-in from STOP counts on row 1, then row 1 plays; REC during the count-in cancels it and stops.
- [ ] OS-LIVEEXIT: in LIVE, REC goes to WATCH and Shift+REC to STEP at the current row; one F8 undoes the take.
- [ ] OS-PLAYCUR: Shift+Play plays from the cursor's row, stopped and playing (`qa_playcur.json`).
- [ ] OS-ZOOM: Note+Instr cycles 5 / 8 / 12 tracks; 12-track text legible at arm's length; a fast Note+Instr roll drops no tap; Note+Left/Right moves a track, Note+Right auto-repeats; boot time with the extra tile upload (compare with v0.5.0).
- [ ] OS-QJUMP: Shift+Note / Instr / FX1 / FX2 jump to 0/4, 1/4, 2/4, 3/4; Shift+Vol and Shift+Fx next to the Learn chord still work.
- [ ] OS-PADINSTR re-test: in STEP, a pad over a step that has another instrument (C-4 06 with instrument 07 current): does the step keep 06? Only report.
